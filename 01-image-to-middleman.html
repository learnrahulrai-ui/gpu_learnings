01. From (i, j) to the middleman pair (cx, cy)

Each line uses only what the lines above it made. The grey note says which line it takes from. Fill every ____ on paper, then open CHECK. Under each piece of code, a panel reads it in English line by line. Any unfamiliar word: words used on this site.

The story

This site follows one learner through the first labs of MIT course 6.S894, Accelerated Computing, done on a laptop instead of the course machines. The laptop has an AMD Ryzen 5 4600H processor and an NVIDIA GeForce GTX 1650 graphics card. Lab 1 asks for the same picture to be computed four ways: on one processor core, on one core using its 8-numbers-at-once instructions, on the graphics card with one thread, and on the graphics card with 32 threads.

The picture is the Mandelbrot set. You do not need to know anything about it yet. What matters is that the picture is a sheet of 256 by 256 whole numbers, and each of those numbers is the result of a small amount of arithmetic. The lab file computes every one of them and stores it in an array called out.

The learner got stuck before any graphics card appeared, on the first two lines of arithmetic. The learner believed that the place (i, j) in the picture is the thing being computed. It is not. A pair of code lines turns (i, j) into a different pair of fractions, which the learner named the middleman pair, and only the middleman pair goes into the arithmetic. The learner pushed back hard: if a place is (9, 7), why should it become anything else? Hold that question while you calculate: is (9, 7) the same point on every picture size?

The reasoning test hidden in this page is simple to state and easy to fail: which numbers belong to the picture, which belong to the mathematics, and which were typed by a person?

Your words: "Row 2 column 2 will always mean row 2 column 2, right?" / "Basically, I have two different papers, right?" / "What is the guarantee that ... with this middleman number, that number of iterations can change, right?"

L03 The lab file mandelbrot_cpu.cpp has these lines, copied with the while loop shortened to a comment: from: code

for (uint64_t i = 0; i < img_size; ++i) {
    for (uint64_t j = 0; j < img_size; ++j) {
        float cx = (float(j) / float(img_size)) * 2.5f - 2.0f;
        float cy = (float(i) / float(img_size)) * 2.5f - 1.25f;
        /* ... a while loop here makes iters from cx, cy ... */
        out[i * img_size + j] = iters;
    }
}

Read the code in English, line by line

  1. for (uint64_t i = 0; i < img_size; ++i) {Give i the values 0 up to img_size minus 1, one after another.
  2. for (uint64_t j = 0; j < img_size; ++j) {Inside that, give j the values 0 up to img_size minus 1 in the same way, so every pair (i, j) is visited exactly once.
  3. float cx = (float(j) / float(img_size)) * 2.5f - 2.0f;Turn j and img_size into fractions, divide j by img_size, multiply by 2.5, subtract 2.0, and keep the result in a fraction named cx. The f after a number marks it as a 32-bit fraction (a float).
  4. float cy = (float(i) / float(img_size)) * 2.5f - 1.25f;Do the same with i, but subtract 1.25, and keep the result in cy.
  5. /* ... a while loop here makes iters from cx, cy ... */Text between /* and */ is a note for people; the computer ignores it. This note stands in for a loop not copied on this page.
  6. out[i * img_size + j] = iters;Store the whole number iters into the array out, at place number i times img_size plus j.
  7. }End of the block opened by the matching brace above.
  8. }End of the block opened by the matching brace above.

In plain words

A computer picture is a list of samples. The programmer decides which region of the mathematical plane to sample and how many samples to take; the arithmetic never sees the sample's number on the sheet, only the point it stands for. Mixing up "which sample" with "which point" is the first mistake in this lab, and it is a mistake people with a correct definition of every word still make.

For a manager: when two teams report results "for the same input", ask whether they mean the same index or the same underlying value. On this page the same (9, 7) meant two different points.
