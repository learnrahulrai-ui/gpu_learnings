The register budget

Topics: GPU chip. A single idea, with a few lines to calculate. Each line uses only the lines above it, and the grey note names its source. Fill every ____ on paper, then open CHECK. Any unfamiliar word: words used on this site.

The idea

Arithmetic reads its inputs only from registers, small storage cells inside the chip. Each SM has a fixed number of them, shared by all the threads it holds at once, so a kernel that uses more registers per thread lets fewer threads fit.

The question here: when does fewer threads actually mean slower?

Work it out

L01 Turing facts: each SM has 65,536 registers of 32 bits and 4 schedulers, and holds at most 1,024 threads. It handles threads in consecutive sets of 32, which NVIDIA calls warps, so at most 32 warps. from: NVIDIA Turing Tuning Guide

L02 DO Registers per thread with 1,024 threads held = ____ . A kernel using 72 per thread needs 72 x 32 = ____ registers per warp. Warps that fit = 65,536 / ____ = ____ , rounded down to ____ . Threads = ____ . from: L01

CHECK 
65,536 / 1,024 = 64 per thread
72 x 32 = 2,304 per warp
65,536 / 2,304 = 28.4 -> 28 warps = 896 threads (instead of 1,024)

L03 Measured on your GTX 1650: a 32-thread multiply-add takes 2 cycles to begin, and one that needs the previous result waits 4 cycles; so when each warp is one chain of multiply-adds, 4 / 2 = 2 warps per scheduler keep the FP32 units busy. from: your output (Lab 2 prelab)

L04 DO At 72 registers: warps per scheduler = 28 / 4 = ____ ; needed = ____ . Slower because of registers? ____ . At 128 registers: warps per SM = 65,536 / (128 x 32) = ____ , per scheduler ____ . Slower? ____ . from: L01, L02, L03

CHECK 
72: 7 per scheduler, 2 needed -> no
128: 65,536 / 4,096 = 16 per SM, 4 per scheduler -> still no
Registers slow a kernel only when the work needs more warps per scheduler than fit.
Read the real use with -Xptxas -v, and measure before blaming registers.
