Which threads are neighbours in memory

Topics: Lab 3, memory. A single idea, with a few lines to calculate. Each line uses only the lines above it, and the grey note names its source. Fill every ____ on paper, then open CHECK. Any unfamiliar word: words used on this site.

The idea

The memory system combines only the addresses that the 32 threads of one instruction supply together. A kernel in which each thread loops over several floats has two candidates for neighbours: the threads of one instruction, or one thread's floats over time.

The question here: how does the index line alone say which of the two it made neighbours, and what must the base of the index be built from?

Work it out

L01 NVIDIA's CUDA programming guide: 32 threads with consecutive thread numbers execute one instruction together, and the memory system serves that one instruction's addresses in pieces of 32 bytes. In Lab 3's copy kernels every thread loops x times, so the threads of one instruction are at the same i. The learner's index: idx = tid * x + i. from: the CUDA programming guide; the Lab 3 starter; the learner's code

L02 DO Expand idx = blockIdx.x * blockDim.x * x + threadIdx.x * ____ + i * ____ . Which variable carries the multiplier 1, and so which floats sit side by side? ____ . With the starter's x = 1024, pieces per instruction: ____ . from: L01

CHECK 
threadIdx.x * x, i * 1: the 1 sits on i, so one thread's floats are neighbours over time and
the 32 floats of one instruction are 4,096 bytes apart: 32 pieces instead of 4

L03 DO To put the 32 floats of one instruction side by side, which quantity must the base be built from, and which must be the small step? ____ . By how much does such a base move per instant? ____ . from: L01, L02

CHECK 
the base from what the threads share at one instant, i (plus a corner per block if each
block owns a region); the step from what tells them apart, the thread's own number
the base moves by the number of threads walking together, one float used up per thread
