The story

Students enrolled in MIT 6.S894 send their code to the course's machines with a tool called telerun. A self-learner has no account there, so in this tutorial every lab is compiled and timed on your own computer. That changes three things: which CPU instructions you can use, which GPU you have, and every number you measure.

The starter program can be compiled and executed before you write a single line of your own. It times the reference function, compares your function with it, and prints a result even while your function is still empty.

What does a function that does nothing print, and how does that one number tell you whether your setup works?

Guess first

The Lab 1 starter's vector function is empty, yet the program still compares it with the reference and prints an "average output difference". Guess the printed number: 0, 1, or something in between? If in between, write your best value.

Work it out

L01 The Lab 1 handout targets AVX-512: CPU instructions that act on 512 bits at once. A float is 32 bits. The laptop used in this tutorial, a Ryzen 5 4600H, has AVX2 instead, which acts on 256 bits. from: Lab 1 handout (Fall 2025), your hardware table

L02 Ask your own CPU which of the two it has (Linux or WSL2): from: Linux /proc/cpuinfo

grep -o -w -e avx2 -e avx512f /proc/cpuinfo | sort -u

Read the code in English, line by line

  1. grep -o -w -e avx2 -e avx512f /proc/cpuinfo | sort -uSearch the CPU's own description for the words avx2 and avx512f, and print each word found, once.

L03 DO Floats per AVX-512 instruction = 512 / 32 = ____ . Floats per AVX2 instruction = ____ . Words your CPU printed for L02: ____ . Floats per instruction your Lab 1 vector code can use = ____ . from: L01, L02

CHECK 
AVX-512: 16 floats; AVX2: 8 floats
the laptop prints only avx2 (its Zen 2 cores have no AVX-512), so its vector code uses 8
AVX-512 code on a CPU without it stops with "Illegal instruction" at the first such instruction.

L04 An NVIDIA GPU belongs to a generation, named by its compute capability; the GTX 1650 is 7.5 (Turing). The nvcc flag -arch=sm_75 makes nvcc produce machine instructions for 7.5, so a listing of the compiled file shows what that GPU executes. from: CUDA programming guide (compute capabilities), nvcc documentation

L05 Ask your GPU and your CUDA toolkit: from: NVIDIA driver, CUDA toolkit

nvidia-smi --query-gpu=name,compute_cap --format=csv
nvcc --version

Read the code in English, line by line

  1. nvidia-smi --query-gpu=name,compute_cap --format=csvAsk the NVIDIA driver for the GPU's name and compute capability, printed as comma-separated text.
  2. nvcc --versionPrint the version of the CUDA compiler.

L06 DO Your GPU name = ____ , compute capability = ____ , so your flag is -arch=sm_ ____ . Your nvcc version = ____ . from: L04, L05

CHECK 
the laptop: NVIDIA GeForce GTX 1650, 7.5 -> -arch=sm_75, nvcc release 12.4
If nvcc stops with "unsupported GNU version", your g++ is newer than your CUDA version accepts:

L08 What mandelbrot_cpu.cpp contains: mandelbrot_cpu_scalar, the reference, already written; mandelbrot_cpu_vector, empty, which the lab asks you to write; and a main that computes the reference once, then times each version and prints its time, and for the vector version also an "average output difference from reference". The picture is 256 by 256 places with at most 1000 repetitions each, unless the flags -r and -b say otherwise. from: Lab 1 starter code

L12 The starter's check: before the vector version is timed, main fills result with 0; afterwards it adds up, over every place, the gap between result and the reference's iters, and divides by img_size x img_size x max_iters. from: Lab 1 starter code (memset, difference)

L13 Real data: the reference's iters for the 256 by 256 picture, max_iters = 1000, add up to 16,274,722 on the laptop (its "CPU total"). from: your output, computation on the lab code

L14 DO With mandelbrot_cpu_vector still empty, result stays 0 at every place. Printed difference = 16,274,722 / (256 x 256 x 1000) = 16,274,722 / ____ = ____ . Connect the numbers

L18 DO Collect L03 (floats per instruction), L06 (your -arch), L11 (your time against 61.6), L14 (0.248), L17 (the shortest time belongs to an empty function). Write the three numbers every later result is compared against, and one sentence on why a printed time without the printed difference proves nothing. from: L03, L06, L11, L14, L17

CHECK 
(1) your scalar time (the laptop: 61.6 ms), the baseline for every speedup
(2) the difference: 0.248 for an empty function, exactly 0 for a correct one
(3) your floats per instruction: 8 with AVX2, 16 with AVX-512
A time says how long something took, not what it computed: L17's empty functions print
the shortest times of all.

Tempting answer that fails: "it compiled, finished and printed a time, so the setup works".
L17 refutes it: an empty function also compiles, finishes and prints a time.

When it goes wrong

  • No pictures appear in out/. The folder out did not exist when the program executed, and the starter does not report it (L07). Make it and execute again.
  • "Illegal instruction" as soon as the vector version begins. The code uses AVX-512 on a CPU that has only AVX2 (L03). Write the vector version with 8-float AVX2 instructions.
  • nvcc stops with "unsupported GNU version". Your g++ is newer than your CUDA version accepts (L06). Point nvcc at an older g++ with -ccbin.
  • "no kernel image is available for execution on the device". The -arch value does not match your GPU (L04 to L06).
  • Every version prints about 0.248 and a tiny time. The functions are still empty (L14, L17).

In plain words

Before anyone can make a program faster, they need two instruments: a clock, and a check that the output is right. The starter code brings both. The quickest test of both is a function that does nothing: the clock must show it as fast, and the check must show it as completely wrong.

For a manager: a speed number means nothing without the correctness number printed next to it. A report that shows only times can rank a function that does nothing as the best.

The interviewer's next question

The GPU file prints a time of a few microseconds for the empty launch function. A colleague calls it "the cost of one kernel launch" and subtracts it from every later GPU time. What is wrong, and what would measure the cost of a launch?

CHECK 
The empty launch function launches nothing: the time is three calls of an empty CPU function
plus cudaDeviceSynchronize on an idle GPU. A real launch also hands a kernel to the GPU and waits
for it to begin and end. To measure that, time an empty __global__ kernel launched <<<1, 1>>>,
3 times then one cudaDeviceSynchronize, exactly as the starter times the real kernels, and
subtract only measurements taken the same way.
