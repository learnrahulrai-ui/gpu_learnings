Lesson 0. Set up your machine and read the starter program

This lesson comes before Lab 1 and builds nothing. It puts the starter code of both labs on your own computer, compiles it, and reads what the untouched programs print. You need Linux, or Windows with WSL2, with g++ and git, and for the GPU half an NVIDIA GPU with its driver and the CUDA toolkit. Paragraphs with a red rule beside them are for your pencil; work each one before opening its CHECK.

Students enrolled in MIT 6.S894 send their code to the course's machines with a tool called telerun, as the course's handouts describe. This tutorial compiles and times every lab on your own computer instead, and that changes three things: which instructions your CPU has, which GPU executes your code, and every time you measure. The measured numbers on these pages come from one laptop, with a Ryzen 5 4600H CPU and a GTX 1650 GPU, so that yours can be set beside them. The Lab 1 starter program compiles and executes before you write anything: it holds a finished function, the reference, which every version you write is compared with, and empty functions for you to fill, and it prints a time and a comparison with the reference even for the empty ones. What does a function that does nothing print, and what does that number say about whether your setup works?

The first question at this point, asked by the owner of that laptop, was whether any of this depends on installed software:

"Even if I don't install CUDA libraries, even if I don't even open NVIDIA website ever on my laptop, these things just remain, yes or no" / "A block need not exist at all. But wrap scheduler always exists. So why would a wrap scheduler even know about blocks" / "the total number of threads which I can run on my hardware is what? 14 times 4 times 32, is this true or false?"

It does not. The instructions a CPU has and the generation a GPU belongs to are built into the chips, software only reads them, and both can be read before anything is compiled.

Write a guess before compiling anything. The starter's vector function, mandelbrot_cpu_vector, is empty, yet the program still compares its answer with the reference's answer and prints a number it calls the average output difference. Is that number 0, 1 or something in between, and if in between, which value?

Asking your CPU which vector instructions it has

The Fall 2025 Lab 1 handout's vector part uses AVX-512, CPU instructions that act on 512 bits at once, while a float is a fraction stored in 32 bits. The Ryzen 5 4600H in the laptop has AVX2 instead, whose instructions act on 256 bits. On Linux, and on WSL2, the file /proc/cpuinfo lists, among other things, the instruction sets the CPU has, and this command picks out the two that matter here:

grep -o -w -e avx2 -e avx512f /proc/cpuinfo | sort -u

grep searches /proc/cpuinfo for the whole words avx2 and avx512f, -o makes it print only each word it finds, and sort -u sorts what it printed and keeps each word once.

Divide 512 by 32 and 256 by 32 to get the floats each set holds in one instruction. Then execute the command and write which of the two words your CPU printed.

CHECK

AVX-512 holds 512 / 32 = 16 floats per instruction and AVX2 holds 256 / 32 = 8. The laptop printed only avx2, because its cores, of the design AMD calls Zen 2, have no AVX-512, so vector code on it handles 8 floats per instruction.

A CPU refuses an instruction it does not have, and Linux then stops the program with the message Illegal instruction, so code written with AVX-512 instructions stops on such a CPU at the first of them it reaches.

Asking your GPU which -arch it needs

A function that executes on the GPU is called a kernel. An NVIDIA GPU belongs to a generation named by a pair of numbers, its compute capability, which NVIDIA's CUDA programming guide lists for every GPU; the GTX 1650 is 7.5, the generation NVIDIA calls Turing. The nvcc flag -arch=sm_75 makes nvcc produce machine instructions for compute capability 7.5, together with a portable form that a GPU of a later generation can translate, as nvcc's documentation describes. A program compiled with an -arch above your GPU's compute capability therefore cannot start its kernels there, and CUDA reports no kernel image is available for execution on the device as soon as the program launches one. The NVIDIA driver and the CUDA toolkit report what you have:

nvidia-smi --query-gpu=name,compute_cap --format=csv
nvcc --version

nvidia-smi asks the NVIDIA driver for the GPU's name and compute capability and prints them as comma-separated text, and nvcc --version prints the version of the CUDA compiler.

Write your GPU's name and compute capability, the -arch flag that follows from it, and your nvcc version.

CHECK

The laptop reported an NVIDIA GeForce GTX 1650 with compute capability 7.5, so its flag is -arch=sm_75, and its nvcc is release 12.4.

If nvcc stops with unsupported GNU version, your g++ is newer than your CUDA version accepts. NVIDIA's installation guide for your CUDA version lists the g++ versions it accepts, and nvcc's -ccbin option points it at an accepted one once that is installed.

Fetching both labs and reading the CPU file's main

git clone https://github.com/accelerated-computing-class/lab1.git
git clone https://github.com/accelerated-computing-class/lab2.git
cd lab1
mkdir -p out

git clone copies the Lab 1 starter code from the course's public repository into a new folder named lab1, and the second git clone does the same for Lab 2, into lab2. cd lab1 moves into the Lab 1 folder, and mkdir -p out makes a folder named out, into which the programs write their pictures. The starter writes each picture through its function writeBMP, which opens the file with std::ofstream and never checks that the file opened, so without the folder out the program writes no picture and prints nothing about it.

The file mandelbrot_cpu.cpp holds mandelbrot_cpu_scalar, the reference, already written; mandelbrot_cpu_vector, empty, which part 2 of the lab asks you to write; and main, the function where the program begins. Cut to what this lesson uses, main reads:

uint32_t img_size = 256;
uint32_t max_iters = 1000;
enum MandelbrotImpl impl = ALL;
if (ParseArgsAndMakeSpec(argc, argv, &img_size, &max_iters, &impl))
    return -1;
std::vector<uint32_t> result(img_size * img_size);
std::vector<uint32_t> ref_result(img_size * img_size);
mandelbrot_cpu_scalar(img_size, max_iters, ref_result.data());
if (impl == SCALAR || impl == ALL) {
    memset(result.data(), 0, sizeof(uint32_t) * img_size * img_size);
    BENCHPRESS(mandelbrot_cpu_scalar, img_size, max_iters, result.data());
    dump_image("out/mandelbrot_cpu_scalar.bmp", img_size, max_iters, result);
}
if (impl == VECTOR || impl == ALL) {
    memset(result.data(), 0, sizeof(uint32_t) * img_size * img_size);
    BENCHPRESS(mandelbrot_cpu_vector, img_size, max_iters, result.data());
    dump_image("out/mandelbrot_cpu_vector.bmp", img_size, max_iters, result);
    std::cout << "  Correctness: average output difference from reference = "
              << difference(img_size, max_iters, result, ref_result) << std::endl;
}

main sets img_size to 256, max_iters to 1000 and impl, the choice of versions to time, to all of them. ParseArgsAndMakeSpec, defined in the same file, changes img_size when the program is given -r and a size, which must be a multiple of 32, changes max_iters when given -b and a number, and changes impl when given -i scalar or -i vector; it then prints the size and max_iters it ended with, as in Testing with image size 256x256 and 1000 max iterations. main makes two arrays of img_size times img_size 32-bit whole numbers, result and ref_result, and computes the reference once into ref_result: the reference stores one whole number for every pair (i, j), with i and j each from 0 to img_size - 1, at entry i times img_size plus j, as its code in the same file shows. Then, for each version chosen, main sets result to 0 with memset, times the version with the macro BENCHPRESS, whose calls of the version fill result, and writes result as a picture with dump_image; after the vector version it also prints the number that the function difference computes from result and ref_result.

BENCHPRESS and difference are defined in the same file:

static constexpr size_t kNumOfOuterIterations = 10;
static constexpr size_t kNumOfInnerIterations = 1;
#define BENCHPRESS(func, ...) \
    do { \
        std::cout << "Running " << #func << " ...\n"; \
        std::vector<double> times(kNumOfOuterIterations); \
        for (size_t i = 0; i < kNumOfOuterIterations; ++i) { \
            auto start = std::chrono::high_resolution_clock::now(); \
            for (size_t j = 0; j < kNumOfInnerIterations; ++j) { \
                func(__VA_ARGS__); \
            } \
            auto end = std::chrono::high_resolution_clock::now(); \
            times[i] = std::chrono::duration_cast<std::chrono::nanoseconds>(end - start) \
                           .count() / \
                kNumOfInnerIterations; \
        } \
        std::sort(times.begin(), times.end()); \
        std::cout << "  Runtime: " << times[0] / 1'000'000 << " ms" << std::endl; \
    } while (0)

kNumOfOuterIterations is 10 and kNumOfInnerIterations is 1. BENCHPRESS prints the name of the function, makes room for 10 times, and 10 times over reads the clock, calls the function once, reads the clock again and keeps the difference in nanoseconds. Then it sorts the 10 times and prints the smallest, times[0], divided by 1,000,000, so in milliseconds.

double difference(
    uint32_t img_size,
    uint32_t max_iters,
    std::vector<uint32_t> &result,
    std::vector<uint32_t> &ref_result) {
    int64_t diff = 0;
    for (uint32_t i = 0; i < img_size; i++) {
        for (uint32_t j = 0; j < img_size; j++) {
            diff +=
                abs(int(result[i * img_size + j]) - int(ref_result[i * img_size + j]));
        }
    }
    return diff / double(img_size * img_size * max_iters);
}

difference adds up, over every pair (i, j), the size of the gap between result and ref_result, in a 64-bit whole number diff, and returns diff divided by img_size times img_size times max_iters.

Compiling and executing the CPU file

g++ -O3 -march=native -std=c++17 mandelbrot_cpu.cpp -o mandelbrot_cpu
./mandelbrot_cpu

g++ compiles the file with full optimization, -O3, allowing every instruction this CPU has, AVX2 included, -march=native, as 2017 C++, -std=c++17, into the program named by -o, mandelbrot_cpu. ./mandelbrot_cpu executes it with the defaults, 256 by 256 pairs and max_iters 1000: it computes the reference, times the reference with BENCHPRESS, then times the empty vector function and prints its average output difference.

The laptop printed 61.6 ms as the time of mandelbrot_cpu_scalar. Write your own time and divide it by 61.6. Then work out why BENCHPRESS prints the smallest of its 10 times rather than their average, given that another program on the machine can only ever make a call slower.

CHECK

A disturbance only adds time, so the smallest of the 10 times is the one closest to what the code itself costs. The price is that the smallest hides how much the calls varied: times of 10, 11, 10, 30 and 14 ms print as 10.

Your time divided by 61.6 is your machine's time for this function as a multiple of the laptop's.

Working out what the empty vector function prints

Before the vector version is timed, memset sets every entry of result to 0, and BENCHPRESS then calls mandelbrot_cpu_vector, which does nothing, so result is still 0 at every pair when difference reads it. On the laptop, the reference's numbers for the default picture, 256 by 256 pairs with max_iters 1000, add up to 16,274,722, a sum that a loop added to main computed and printed.

With result 0 at every pair, each gap that difference adds is the reference's own number. Work out what difference returns, 16,274,722 divided by 256 times 256 times 1000. Then work it out a second way, as the average number per pair, 16,274,722 / 65,536, divided by max_iters, 1000. What must a correct vector version print?

CHECK 
256 * 256 * 1000 = 65,536,000
16,274,722 / 65,536,000 = 0.2483

256 * 256 = 65,536 pairs
16,274,722 / 65,536 = 248.3 per pair
248.3 / 1000 = 0.2483

Both ways give 0.2483: the empty function is wrong by the whole of every number. A correct version leaves result equal to ref_result at every pair, so every gap is 0 and it prints exactly 0. A machine that prints about 0.248 now has a reference that produced about the laptop's sum and a difference function that computed it.

Compiling the GPU file and reading its timing

The GPU file, mandelbrot_gpu.cu, holds the same reference, computed on the CPU, and for each GPU version a pair of empty functions: the kernel and a launch function that executes on the CPU and is meant to start it.

__global__ void mandelbrot_gpu_scalar(
    uint32_t img_size,
    uint32_t max_iters,
    uint32_t *out /* pointer to GPU memory */
) {
    /* your (GPU) code here... */
}

void launch_mandelbrot_gpu_scalar(
    uint32_t img_size,
    uint32_t max_iters,
    uint32_t *out /* pointer to GPU memory */
) {
    /* your (CPU) code here... */
}

__global__ marks mandelbrot_gpu_scalar as a kernel; it receives img_size, max_iters and out, an address in the graphics card's memory, and its body is left for you. launch_mandelbrot_gpu_scalar is an ordinary function that executes on the CPU, receives the same three values and is meant to start the kernel; its body is empty too, so as given it starts nothing on the GPU.

static constexpr size_t kNumOfOuterIterations = 5;
static constexpr size_t kNumOfInnerIterations = 3;
#define BENCHPRESS(func, ...) \
    do { \
        std::cout << "Running " << #func << " ...\n"; \
        std::vector<double> times(kNumOfOuterIterations); \
        for (size_t i = 0; i < kNumOfOuterIterations; ++i) { \
            auto start = std::chrono::high_resolution_clock::now(); \
            for (size_t j = 0; j < kNumOfInnerIterations; ++j) { \
                func(__VA_ARGS__); \
            } \
            CUDA_CHECK(cudaDeviceSynchronize()); \
            auto end = std::chrono::high_resolution_clock::now(); \
            times[i] = std::chrono::duration_cast<std::chrono::nanoseconds>(end - start) \
                           .count() / \
                kNumOfInnerIterations; \
        } \
        std::sort(times.begin(), times.end()); \
        std::cout << "  Runtime: " << times[0] / 1'000'000 << " ms" << std::endl; \
    } while (0)

Here kNumOfOuterIterations is 5 and kNumOfInnerIterations is 3. Over 5 measurements, BENCHPRESS reads the clock, calls the launch function 3 times, waits with cudaDeviceSynchronize until the GPU has finished everything sent to it, reads the clock again and divides the time by 3; it prints the smallest of the 5 results, in milliseconds. Before timing, the GPU file's main sets the GPU's copy of the result to 0 with cudaMemset, and afterwards it copies the result back to the CPU with cudaMemcpy and prints its average output difference from the reference.

nvcc -O3 -arch=sm_75 -std=c++17 mandelbrot_gpu.cu -o mandelbrot_gpu
./mandelbrot_gpu

nvcc compiles the CUDA file with full optimization for compute capability 7.5, as 2017 C++, into the program mandelbrot_gpu; put your own number in place of 75. ./mandelbrot_gpu computes the reference on the CPU and then times both GPU versions.

Write the average output difference you expect for each empty GPU version, and what the printed time of an empty launch function measures. Then execute the program and write which of all your versions printed the shortest time.

CHECK

Both print about 0.248: the GPU's result stays 0 at every pair, and the reference is the same, so difference returns 16,274,722 / 65,536,000 again. The printed time is 3 calls of an empty CPU function plus one cudaDeviceSynchronize on an idle GPU, divided by 3, so it is tiny.

The empty versions print the shortest times of all, since they do nothing, so a short time next to 0.248 is a function that did nothing.

Gathering the numbers your setup produced

Your CPU's vector instructions hold 8 floats with AVX2 or 16 with AVX-512; your GPU's compute capability gives your -arch; the reference took 61.6 ms on the laptop, with your own time beside it; and an empty function prints an average output difference of 0.2483 while printing the shortest time of all.

Write your floats per instruction, your -arch and your time for the reference, then one sentence on why a printed time without the printed difference proves nothing.

CHECK

A time says how long something took, not what it computed, and the empty functions printed the shortest times of all.

The reading "it compiled, finished and printed a time, so the setup works" fails, because an empty function also compiles, finishes and prints a time, next to a difference of 0.2483.

Illegal instruction as soon as a vector version begins means AVX-512 code on a CPU that has only AVX2. unsupported GNU version from nvcc means a g++ newer than your CUDA version accepts. no kernel image is available for execution on the device means an -arch above your GPU's compute capability. The quiet failures are worse: a missing out folder leaves no pictures and no message, and an empty launch function leaves 0.248 and a tiny time.

Before a program can be made faster, two instruments are needed: a clock, and a check that the output is right. A function that does nothing tests both at once, because the clock must show it as fast and the check must show it as completely wrong. A speed number means nothing without the correctness number next to it, and a report that shows only times can rank a function that does nothing first.

The number asked for before compiling is in between: about 0.248, which is 16,274,722 / 65,536,000, the average of 248.3 per pair divided by 1000.

The GPU file prints a tiny time for the empty launch function, and a colleague calls it the cost of one kernel launch and subtracts it from every later GPU time. What is wrong with that, and what would measure the cost of a launch?

CHECK

The empty launch function launches nothing, so its time is 3 calls of an empty CPU function plus cudaDeviceSynchronize on an idle GPU. A real launch also hands a kernel to the GPU and waits for it to begin and end.

Timing a launch function that does start a kernel, one whose body is empty, called 3 times and followed by one cudaDeviceSynchronize, exactly as BENCHPRESS times the real versions, measures that cost, and only measurements taken the same way may be subtracted from each other.
