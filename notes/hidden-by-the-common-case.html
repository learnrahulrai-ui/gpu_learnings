Bugs hidden by the common case

Topics: real bugs, GPU chip. A single idea, with a few lines to calculate. Each line uses only the lines above it, and the grey note names its source. Fill every ____ on paper, then open CHECK. Any unfamiliar word: words used on this site.

The idea

Some faults in widely used GPU libraries stayed hidden for months or years, not because nobody tested, but because every usual test produces exactly the right answer.

The question here: what do such faults have in common, and which input exposes each of them?

Work it out

L01 CUTLASS issue 1094 (2023): __shfl_sync(0x1f, threadIdx.x / 32, 0) worked on an A100 and failed on an H100; 0x1f names threads 0 to 4 of 32. NVIDIA Warp issue 2282 (2026): a distance in bytes divided by sizeof(T) reads padded vec3 arrays from floats 0, 3, 6 instead of 0, 4, 8. NVIDIA Warp issue 2294 (2026): a kernel requested 4,224 bytes of shared memory and needed 4,288; with a smaller size the same 64-byte shortfall launched fine. from: CUTLASS issue 1094; NVIDIA Warp issues 2282 and 2294

L02 DO Which input shows each fault? Shuffle: ____ . Division: ____ . Count: ____ . from: L01

CHECK 
shuffle: a GPU that enforces the mask rule (the H100); on the A100 the copied value equalled what
every thread already had
division: an array whose element distance is not a multiple of the element size (padded vec3)
count: sizes at which the memory past the request is not usable (K = 16, not K = 13)

Worked out in full

  • 41. CUTLASS 1094: a shuffle mask that named 5 of the 32 threads executing it
  • 42. NVIDIA Warp 2282: a distance in bytes divided by the size of an element
  • 43. NVIDIA Warp 2294: shared memory counted before a later line moved the tile
