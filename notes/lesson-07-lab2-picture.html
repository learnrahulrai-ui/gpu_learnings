The story

Lab 2 computes a bigger and deeper picture: 1024 by 1024 places, up to 2000 repetitions each, inside a window one ten-thousandth across. Its files invite you to paste in your Lab 1 vector code for comparison, updated to the new window constants.

The move brings two small changes. The window is set by window_zoom, window_x and window_y instead of 2.5, 2.0 and 1.25. And one line of the loop is written differently, w - (x2 + y2) + cy instead of w - x2 - y2 + cy, which is the same in exact arithmetic.

When your port prints a small difference instead of 0, is it a bug or rounding, and how can you tell?

Guess first

Lab 2 prints one wrong place as 1 / (1024 x 1024 x 2000). A first version forgets a whole value of i (1024 places); a second only changes rounding. Guess which prints the smaller number.

Write your guess on paper now, before any calculation on this page.

When it goes wrong

  • Difference about 0.045. The window constants are wrong, often a sign (L08).
  • Difference about 0.0076. Line B is still in the Lab 1 form (L04, L05).
  • Difference below 0.0001 but not 0. Places are missing, such as one whole value of i (L07).
  • Your speedup changes from one execution to the next. Executions differ by 7 percent on their own (L13); compare several of each.

In plain words

Lab 2 zooms 25,000 times deeper into the same picture. At that depth, neighbouring points differ by only one or two steps of the computer's number format, so a harmless-looking rewrite of one line changes the result at a quarter of the places. Only an exact match counts as correct.

For a manager: a summary error figure can rank a seriously broken version above a harmless one. Ask how many results differ, not only by how much on average.

The interviewer's next question

Your port prints 0.000000000477. Is it correct, and what do you do next?

CHECK 
No: 4.77e-10 is exactly one place wrong by 1, so the new version is not correct yet. Add a count
of mismatched places, and print the first one's i, j and both values. Then find the cause: a real
bug, or a rounding difference such as a reordered line B, which must be matched to the reference
before any speed comparison.
