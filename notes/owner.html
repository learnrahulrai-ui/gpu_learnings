Owner: exactly one writer per place

Topics: splitting work. A single idea, with a few lines to calculate. Each line uses only the lines above it, and the grey note names its source. Fill every ____ on paper, then open CHECK. Any unfamiliar word: words used on this site.

The idea

When several workers, CPU threads or GPU threads, compute one picture, each place must be written by exactly one of them, its owner. A place with two owners is written twice; a place with none keeps whatever was there. A split can be correct and still slow, when one owner gets far more work than the rest.

The question here: on the real Lab 2 picture, how much does the shape of a correct split matter?

Work it out

L01 The Lab 2 picture: 1024 by 1024 places, max_iters = 2000. Each place costs some number of repetitions of the while loop; computed in 32-bit fractions from the starter's own constants, they total 138,219,822. from: Lab 2 starter code, computation

L02 Split by i among 6 owners in bands: [0, 171), [171, 342), [342, 513), [513, 684), [684, 855), [855, 1024). Repetitions per band: 20,219,285; 20,203,424; 28,346,172; 29,263,472; 19,303,420; 20,884,049. Split in turns instead (owner t takes i = t, t + 6, t + 12, ...): 23,029,821; 23,043,321; 23,099,034; 23,079,169; 22,974,325; 22,994,152. from: same computation

L03 DO The job ends with the owner that has the most work. Bands: speedup over one worker = 138,219,822 / ____ = ____ . Turns: 138,219,822 / ____ = ____ . In turns, owner of i = 1023 = ____ ; why can no i have two owners? ____ . from: L01, L02

CHECK 
bands: 138,219,822 / 29,263,472 = 4.72
turns: 138,219,822 / 23,099,034 = 5.98
1023 = 170 x 6 + 3 -> owner 3; each i has exactly one remainder when divided by 6
Both splits are correct; only the turns give every owner similar work.

L04 DO GPU: <<<2, 32>>> makes 2 blocks of 32 threads; threadIdx.x goes from 0 to 31 in every block and blockIdx.x is the block's number. If each thread owns place threadIdx.x, block 1's thread 0 owns place ____ , the same as block ____ 's thread 0. With place blockIdx.x * 32 + threadIdx.x, block 1's thread 0 owns ____ . from: CUDA programming guide

CHECK 
without blockIdx.x: place 0, the same as block 0's thread 0 -> two owners, and places 32 to 63 have none
with blockIdx.x * 32 + threadIdx.x: place 32
