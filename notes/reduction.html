Adding up an array: chain or tree

Topics: chains. A single idea, with a few lines to calculate. Each line uses only the lines above it, and the grey note names its source. Fill every ____ on paper, then open CHECK. Any unfamiliar word: words used on this site.

The idea

Adding up an array looks like the easiest program there is: one loop and one total that every add updates. Each add needs the total the previous add produced, so the adds form one chain, and a float total can hold only so much precision.

The question here: what does adding in a tree order change, the time, the answer, or both?

Work it out

L01 The plain loop: for (k = 0; k < n; ++k) s = s + x[k]; In English: add each value into s, one after another; each add reads the s that the add before it wrote, so the n adds form one chain. from: code (the standard tutorial program)

L02 Measured on your GTX 1650 in the Lab 2 prelab: a multiply-add that needs the previous one's value waits 4 cycles; on Turing an add waits the same 4 cycles. This note assumes 1.5 billion cycles per second. from: your output, Jia et al. 2019, assumption

L03 DO n = 20,000,000. Plain loop: cycles = 20,000,000 x 4 = ____ ; time = ____ ms, however many threads exist. Tree (add neighbouring pairs, then pairs of those totals, until one is left): adds = ____ ; levels = ____ (2^24 = 16,777,216 and 2^25 = 33,554,432). from: L01, L02

CHECK 
80,000,000 cycles, 80,000,000 / 1.5e9 = 53.3 ms
each add turns two totals into one: 20,000,000 - 1 = 19,999,999 adds
16,777,216 < 20,000,000 <= 33,554,432 -> 25 levels
Almost the same number of adds; the longest chain is 25 instead of 20,000,000.

L04 Float fact: a float holds 24 significant bits, so between 16,777,216 (2^24) and 33,554,432 the floats are 2 apart. A result halfway between two floats goes to the one whose last bit is 0. from: IEEE 754 float32

L05 DO Plain loop over 20,000,000 ones in floats: after 16,777,216 adds, s = 16,777,216. The next add gives 16,777,217, halfway between 16,777,216 and 16,777,218; it becomes ____ . Final s = ____ . Error = ____ percent. The tree order, computed in 32-bit fractions, gives 20,000,000. from: L01, L04, computation

CHECK 
16,777,216 (2^24 ends in a 0 bit); every later add of 1 rounds back to it
final s = 16,777,216
3,222,784 / 20,000,000 = 16.1 percent short
The tree adds totals of similar size, so rounding never swallows what is added;
the same tree shape also shortens the chain to 25 levels.
