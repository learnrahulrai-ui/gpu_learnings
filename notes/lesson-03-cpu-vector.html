The story

The second part of Lab 1 asks for the same picture computed with explicit vector instructions: one instruction acting on several places at once. The handout uses AVX-512, 16 floats per instruction; the laptop in this tutorial has AVX2, 8 floats. Everything below is written for 8; with AVX-512, replace 8 by 16.

A direct translation meets two problems. The reference computes cx from one j, but a vector needs 8 different cx at once. And each place leaves the while loop after its own number of repetitions, while every instruction acts on all 8.

How do 8 places with different counts share one loop, and what does the sharing cost?

Guess first

Work it out

L01 AVX2 facts in C++: __m256 holds 8 floats at index 0 to 7; _mm256_set1_ps(a) puts a at all 8 indexes; _mm256_set_ps(e7, e6, e5, e4, e3, e2, e1, e0) takes its arguments from index 7 down to index 0; add, subtract and multiply act index by index; _mm256_fmadd_ps(a, b, c) computes a times b plus c at each index. from: Intel intrinsics guide

L02 The vector code takes 8 neighbours at once: the same i, and j, j + 1, ..., j + 7, with j a multiple of 8. The reference computes cx = j / img_size x 2.5 - 2.0 for each j. from: your code, reference code

L03 DO Split cx at j + k: (j + k) / img_size x 2.5 - 2.0 = (j / img_size x 2.5 - 2.0) + k x ____ . With img_size = 256 the step = 2.5 / 256 = ____ . For j = 64: cx at k = 0 = ____ , at k = 7 = ____ . from: L02

CHECK 
cx(j + k) = cx(j) + k x (2.5 / img_size)
2.5 / 256 = 0.009765625
j = 64: k = 0 -> -1.375; k = 7 -> -1.375 + 7 x 0.009765625 = -1.306640625
So one vector of offsets 0 to 7, times the step, plus the cx of j, gives all 8 cx in one
instruction: _mm256_fmadd_ps(offsets, step, cx of j).

L04 The learner's code for the 8 cx values, copied from page 04 of the lab pages: from: your code

__m256 offsets = _mm256_set_ps(7, 6, 5, 4, 3, 2, 1, 0);
float  dx      = 2.5f / float(img_size);
for (uint64_t i = 0; i < img_size; ++i) {
    float  cy     = (float(i) / float(img_size)) * 2.5f - 1.25f;
    __m256 cy_vec = _mm256_set1_ps(cy);
    for (uint64_t j = 0; j < img_size; j += 8) {
        float  cx     = (float(j) / float(img_size)) * 2.5f - 2.0f;
        __m256 cx_vec = _mm256_fmadd_ps(offsets, _mm256_set1_ps(dx), _mm256_set1_ps(cx));
        /* the while loop works on cx_vec, cy_vec here */
    }
}

Read the code in English, line by line

  1. __m256 offsets = _mm256_set_ps(7, 6, 5, 4, 3, 2, 1, 0);Make a 256-bit variable named offsets that holds 8 fractions. The instruction _mm256_set_ps fills them from index 7 down to index 0 with the listed values, so index k holds k.
  2. float dx = 2.5f / float(img_size);Make one fraction dx: 2.5 divided by img_size.
  3. for (uint64_t i = 0; i < img_size; ++i) {Give i the values 0 up to img_size minus 1, one after another.
  4. float cy = (float(i) / float(img_size)) * 2.5f - 1.25f;Compute one cy for this value of i, the same way as the scalar code.
  5. __m256 cy_vec = _mm256_set1_ps(cy);Copy that one cy into all 8 indexes of a 256-bit variable named cy_vec.
  6. for (uint64_t j = 0; j < img_size; j += 8) {Give j the values 0, 8, 16, and so on: each step of this loop covers 8 values of j at once.
  7. float cx = (float(j) / float(img_size)) * 2.5f - 2.0f;Compute one cx, for the j this loop is at, the same way as the scalar code.
  8. __m256 cx_vec = _mm256_fmadd_ps(offsets, _mm256_set1_ps(dx), _mm256_set1_ps(cx));At each of the 8 indexes, multiply offsets by dx and add cx, all in one instruction (fmadd = fused multiply-add). Keep the 8 results in cx_vec.
  9. /* the while loop works on cx_vec, cy_vec here */A note for people: the loop that uses cx_vec and cy_vec goes here; it is not copied in this block.
  10. }End of the block opened by the matching brace above.
  11. }End of the block opened by the matching brace above.

L05 DO In L04, which index holds offset 0? ____ . If the offsets were written _mm256_set_ps(0, 1, 2, 3, 4, 5, 6, 7), index 0 would hold ____ , and the 8 results of each block would be stored ____ . from: L01, L04

CHECK 
_mm256_set_ps(7, 6, 5, 4, 3, 2, 1, 0) puts 0 at index 0 and 7 at index 7
written 0, 1, ..., 7: index 0 holds 7, so every block of 8 is stored mirror-reversed
(_mm256_setr_ps takes its arguments in index order instead)

L06 The learner's vector while loop, with lines A to F shortened, copied from page 05: from: your code

__m256  four      = _mm256_set1_ps(4.0f);
__m256i iters_vec = _mm256_setzero_si256();
uint32_t iter = 0;
while (iter < max_iters) {
    __m256 mask = _mm256_cmp_ps(_mm256_add_ps(x2_vec, y2_vec), four, _CMP_LE_OQ);
    if (_mm256_testz_ps(mask, mask)) break;
    iters_vec = _mm256_sub_epi32(iters_vec, _mm256_castps_si256(mask));
    /* lines A to F, each one an _mm256_..._ps instruction */
    ++iter;
}

Read the code in English, line by line

  1. __m256 four = _mm256_set1_ps(4.0f);Copy the fraction 4.0 into all 8 indexes of a variable named four.
  2. __m256i iters_vec = _mm256_setzero_si256();Make 8 whole-number counters, all 0, in one 256-bit variable named iters_vec. The i at the end of __m256i means whole numbers.
  3. uint32_t iter = 0;Make one whole-number counter named iter, holding 0. It counts how many times the loop itself repeats.
  4. while (iter < max_iters) {Repeat the lines in braces as long as iter is below max_iters.
  5. __m256 mask = _mm256_cmp_ps(_mm256_add_ps(x2_vec, y2_vec), four, _CMP_LE_OQ);At each index, add x2 and y2, then compare the sum with 4. Where the sum is at most 4, put 32 bits all set to 1; elsewhere put 32 bits all 0. Keep the 8 answers in mask.
  6. if (_mm256_testz_ps(mask, mask)) break;If all 256 bits of mask are 0, leave the while loop immediately.
  7. iters_vec = _mm256_sub_epi32(iters_vec, _mm256_castps_si256(mask));Read the bits of mask as 8 whole numbers, and subtract them from the 8 counters, index by index.
  8. /* lines A to F, each one an _mm256_..._ps instruction */A note for people: lines A to F go here, each written as an instruction that acts on all 8 indexes.
  9. ++iter;Add 1 to iter.
  10. }End of the block opened by the matching brace above.

L07 Intrinsic facts: _mm256_cmp_ps(..., _CMP_LE_OQ) writes 32 bits all 1 at each index where x2 + y2 <= 4 and 32 bits all 0 elsewhere; that is mask. _mm256_testz_ps(mask, mask) returns 1 when all 256 bits are 0. _mm256_sub_epi32 subtracts index by index, reading the bits as whole numbers. from: Intel intrinsics guide

L08 DO Add 1 in binary to the 32-bit integer whose bits are all 1: the result in 32 bits = ____ , so all ones read as a signed integer = ____ . At an index where mask is all ones, iters - mask = iters + ____ ; where all zeros, iters + ____ . from: L07

CHECK 
11111111 11111111 11111111 11111111 + 1 = 1 00000000 ... 0: the leading 1 does not fit,
the 32 bits left are 0, so all ones = -1
all ones: iters - (-1) = iters + 1; all zeros: iters - 0 = iters
Each index counts itself, with no if.

L09 DO Real block, i = 40, j = 208 to 215, scalar iters 12, 8, 7, 6, 6, 6, 5, 5. An index with scalar iters c has mask all ones before repetitions 1 to c and all zeros after (a point farther than 2 from (0, 0) never comes back). Repetitions of the vector loop = ____ . iters_vec after repetition 7 = ____ . from: L06, L07, L08

CHECK 
testz returns 1 before repetition 13 (index 0, with 12, is the last one inside): 12 repetitions
after repetition 7: 7 7 7 6 6 6 5 5; after 12: 12 8 7 6 6 6 5 5 = the scalar iters

Measure it

Connect the numbers

L15 DO Collect L05 (offsets order), L09 (each index counts itself), L14 (15.2 percent in one block, 88.8 percent overall, 7.11 predicted, 7.07 measured, 2.23 shuffled). The same instructions give 7.11 or 2.23. Write one sentence on what decides the speedup of 8 places per instruction. from: L05, L09, L14

CHECK 
Neighbouring places usually need similar numbers of repetitions, so most blocks of 8 finish
together and waste little; only blocks on the edge of the set mix 1000 with small counts.
The 7 times comes from that property of the picture, not from the instructions: shuffled
blocks give 2.23 with the same code.

Tempting answer that fails: "8 floats per instruction, so 8 times minus overhead". L14 refutes
it: the same code predicts 2.23 when the places in each block are not neighbours.

When it goes wrong

  • Each block of 8 comes out mirror-reversed. The offsets were written 0, 1, ..., 7 into _mm256_set_ps (L05).
  • Correct at 256 but mismatches at a size such as 384. 2.5 / img_size is exact in a float only when img_size is a power of 2; cx built by steps then rounds differently from the reference's division.
  • The loop never ends, or always takes max_iters repetitions. The test of L07 uses the wrong mask, or the repetition counter is not compared with max_iters.
  • A crash (segmentation fault) at the store. _mm256_store_si256 needs an address that is a multiple of 32 bytes, and the starter's out is not guaranteed to be one; _mm256_storeu_si256 accepts any address (L10).

In plain words

Processing 8 places with one instruction is close to 8 times faster only because neighbouring places of this picture need similar amounts of work. Mixed with unlike places, the same instructions gain barely 2 times.

For a manager: the gain from doing several things at once depends on how alike those things are. A benchmark on friendly data does not carry over to mixed data.
