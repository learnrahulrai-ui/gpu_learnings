Lesson 8. Independent work inside one thread

This lesson covers part 1 of Lab 2, where you write mandelbrot_cpu_vector_ilp, mandelbrot_gpu_vector_ilp and its launch, beginning from the ported Lab 2 vector versions. Paragraphs with a red rule beside them are for your pencil; work each one before opening its CHECK.

Part 1 of Lab 2 asks each loop to carry several independent sets of places at once, so that while one set waits for a result another can compute. On the CPU a set is one more vector of 8 places, and on the GPU it is one more place per thread. In the way stand three questions: which line waits for which, how a loop carrying two sets knows when to stop, and why a second place per GPU thread can leave the time unchanged or even double it. When does a second independent set fill waiting time, and when is there no waiting left to fill?

The loop that carries two sets is the fat while loop, and the confusion it caused at this step sounded like this:

"My while loop becomes longer and fatter. Then what is a pass? A pass is a collection of a fat while loop or a thin while loop?" / "It was already difficult to do for 8. Now I have to do for 16." / "My brain refuses to see that I actually solved the problem in lab 1."

Write a guess. On the GTX 1650, the Lab 2 GPU baseline with one block of 32 threads took about 208 ms. With two places per thread, in a correct version, do you expect about 104 ms, about 160 ms, or about 230 ms?

A repetition of the Lab 2 loop takes 16 cycles along its chain

Lines A to F of the Lab 2 loop are x = x2 - y2 + cx, y = w - (x2 + y2) + cy, x2 = x times x, y2 = y times y, z = x + y and w = z times z. The while check computes x2 + y2 before each repetition, and the compiler reuses that sum in line B, so the laptop's listing showed 9 float instructions per repetition, 6 adds and 3 multiplies. Each value is ready 4 cycles after its operation begins, as the prelab measured on this GPU.

Take the y of one repetition as ready at cycle 0. Work out when y2 is ready, when z = x + y is, when w = z times z is, when the next check's x2 + y2 is, when w - (x2 + y2) is, and when the next y is. How many cycles does one repetition take along this chain?

CHECK 
y2 at 4, z at 4, w at 8, x2 + y2 at 8, w - (x2 + y2) at 12, next y at 16

A repetition takes 16 cycles, and the chain that repeats from one repetition into the next is 4 operations long: w - (x2 + y2), then + cy, then x + y, then z times z.

On the laptop's GPU the instructions already fill those 16 cycles

The GTX 1650 is built from 14 identical blocks of hardware that NVIDIA calls SMs, each with 4 schedulers, the circuits that pick which instruction begins next. Measured on this GPU in the prelab, a float instruction for 32 threads takes 2 cycles to begin, and NVIDIA's Turing tuning guide gives a scheduler at most one instruction begun per cycle.

With one set of places per thread, work out the cycles to begin its 9 float instructions and set them beside the 16 cycles of the chain. With two independent sets, work out the same, the cycles per set, and the saving. Then repeat both for a GPU that begins a 32-thread float instruction every cycle.

CHECK 
laptop, one set:  9 x 2 = 18 cycles of begins against a 16-cycle chain -> 18
laptop, two sets: 18 x 2 = 36 cycles -> 18 per set, saving 0 percent
1 cycle per begin, one set:  the larger of 9 and 16  = 16
1 cycle per begin, two sets: the larger of 18 and 16 = 18 -> 9 per set, saving (16 - 9) / 16 = 44 percent

A second set fills only waiting that exists, and on the laptop's GPU, with one set of 32 threads per scheduler, the begins already fill the chain's 16 cycles.

The laptop's CPU differs. Agner Fog's published instruction tables for its Zen 2 cores give a wait of 3 cycles for an add or multiply that needs the previous result, and at least 2 vector float instructions begun per cycle.

For one 8-place set on the CPU, work out the chain, 4 x 3 cycles, and the begins, 9 / 2 cycles. How many sets fill the wait, and how many cycles per set do 1, 2 and 3 sets cost?

CHECK 
chain 12 cycles; begins 4.5 cycles; 12 / 4.5 = 2.7 sets fill the wait
1 set: 12 cycles
2 sets: the larger of 9 and 12 = 12 -> 6 per set
3 sets: the larger of 13.5 and 12 = 13.5 -> 4.5 per set

On this CPU a second and a third set should help, and on this GPU with one set of 32 threads per scheduler they should not.

A loop carrying two sets may stop only when both masks are empty

while (iter < max_iters) {
    maskA = (x2A + y2A <= 4)        maskB = (x2B + y2B <= 4)
    /* stopping test: ____ (not decided yet) */
    itersA = itersA - maskA         itersB = itersB - maskB
    lines A..F on set A             lines A..F on set B
    ++iter;
}

Read in English, and written in short form rather than real C++, the fat while loop repeats while iter is below max_iters; it compares set A's x2 plus y2 with 4 at each index, and the same for set B; it leaves a blank for the rule that decides when to leave the loop, and deciding that rule is the exercise; it subtracts each set's mask from that set's counters, index by index; it does lines A to F for set A and for set B in the same repetition; and it adds 1 to iter.

Take real counts from the Lab 1 picture at i = 40: set A, j = 208 to 215, needs 12, 8, 7, 6, 6, 6, 5 and 5, and set B, j = 216 to 223, needs 5 at every index. If the loop is left when maskB is all zeros, how many repetitions does it make and what counts does set A get? If it is left when maskA is all zeros and set B is counted with no mask, what counts does set B get? What is the right test?

CHECK

Left on maskB, the loop makes 5 repetitions and set A gets 5 at every index, 6 of 8 wrong. Left on maskA with B counted without its mask, set B gets 12 at every index, all wrong. The right test leaves the loop only when maskA and maskB are both all zeros, while each mask still stops its own indexes.

Work out what the right test costs. Thin loops, A alone and then B alone, need 12 + 5 repetitions; the fat loop needs as many repetitions as the slower set. Over the whole Lab 1 picture, pairing each vector of 8 places with the next, thin loops need 2,290,207 repetitions and fat loops 1,236,522. Work out the ratio and the best a pair can give.

CHECK

Thin loops need 12 + 5 = 17 repetitions and the fat loop 12, each doing both sets: set B keeps computing uselessly after its 5, yet the repetitions fall from 17 to 12. Over the whole picture 2,290,207 / 1,236,522 = 1.85, against 2.0 for a pair whose two vectors need the same.

A second place per GPU thread gave 461 ms, then 231 ms, against 208

for (uint64_t j = threadIdx.x * 2; j < img_size; j += blockDim.x * 2) {
    float cx0 = (float(j) / float(img_size)) * window_zoom + window_x;
    /* cx1 for j + 1, then both places' loops */
}

Read in English, each thread's j begins at twice its number and grows by twice the number of threads in the block while it stays below img_size; for each j the thread computes cx0, the cx of place j with Lab 2's window, j divided by img_size, times window_zoom, plus window_x, and the comment stands for cx1 of place j + 1 followed by both places' loops.

With 32 threads, one round of the j loop covers 64 places. List the places thread 0 takes for i = 0. Call the thread that writes a place its owner. If only the first place were doubled, j beginning at twice the thread's number and growing by 32, how many of the 1024 places would have two owners? If only the step were doubled, j beginning at the thread's number and growing by 64, how many would have none?

CHECK

Thread 0 takes 0, 1, 64, 65, 128, 129 and so on. Doubling only the first place leaves 32 places with one owner and 992 with two; doubling only the step leaves 496 places with no owner, 33 to 63 in every 64, 496 with two and 32 with one.

The laptop measured two versions against the baseline of one place per thread, three executions each. The first, with a condition wrapped around each place's arithmetic, took 460.74, 461.50 and 460.84 ms against 222.90, 207.55 and 208.67, and in its listing 18 of the loop's 35 instructions were control. The second, computing both places every repetition and only counting the unfinished one, took 230.89, 231.50 and 232.01 ms against 221.11, 207.87 and 207.82. Both printed a difference of exactly 0.

Work out 460.74 / 222.90 and 231.50 / 207.87, and the share of the first version's loop that is control.

CHECK 
first version:  460.74 / 222.90 = 2.07, and 2.22 for the other executions
second version: 231.50 / 207.87 = 1.114, slightly slower
control: 18 / 35 = 51 percent of the loop decided where to go, not what to compute

The 32 threads are one warp, NVIDIA's name for a set of 32 threads that begin each instruction together; call one repetition of the loop by the whole warp a warp-repetition. Computed from the Lab 2 counts, the baseline needs 8,792,320 warp-repetitions and the second version 5,470,868. Work out the ratio. If a second-version repetition cost the same as a baseline one, what would the time ratio be, and what if it cost twice as much? From the measured 1.114, what does one second-version repetition cost?

CHECK 
5,470,868 / 8,792,320 = 0.622
cost 1 -> 0.622;  cost 2 -> 1.244;  measured 1.114 -> 1.114 / 0.622 = 1.79

The ratio is 0.622, not 0.5, because a set of 64 places waits for the slowest of 64. The second place nearly doubled the cost of a repetition, as the begin count predicted: one set's 18 cycles of begins already filled the 16-cycle chain.

Your CPU version with two sets should come close to 1.85 times

Time your CPU version with 2 sets against your vector version and write the ratio. Under the CPU calculation above, two sets cost the same 12 cycles per repetition as one, so the ratio predicted for the Lab 1 picture is the 1.85 of thin against fat repetitions; compute the Lab 2 picture's the same way from its counts.

CHECK

The laptop's CPU times for this part were not recorded, so your ratio is the first measurement of it; 1.85 is the prediction for the Lab 1 picture.

A second set fills only the waiting that exists

Gathered together, the chain of the Lab 2 loop takes 16 cycles per repetition; on the laptop's GPU the begins take 18, so a second set saves nothing, while on its CPU 2.7 sets fill the wait; the fat loop's cost leaves 1.85 instead of 2; the GPU's first version was 2.2 times slower and its second 1.11; and a second-version repetition cost 1.79 baseline repetitions.

Write one sentence: what single comparison decides whether a second independent set inside a thread helps?

CHECK

The time along the chain against the time to begin all the instructions of one set: a second set fills only the difference. On the CPU core the chain, 12 cycles, is far longer than the begins, 4.5, so sets help; on the GPU with one set of 32 threads per scheduler the begins, 18, already exceed the chain, 16, so the second place mostly adds work.

The reading "32 threads on 32 places are 32 independent chains, so the wait is already hidden" fails: they are 32 sets of data on one instruction stream, all 32 wait when that instruction waits, and only another instruction can fill the wait.

The Fall 2025 handout's first question asks what speedup more independent work per loop gives on the CPU and on the GPU, how the places were split, and what limits the gain; the CPU calculation and your own ratio answer the first part for the CPU, the measured 1.114 and its 1.79 for the GPU, and the 1.85 together with the chain against the begins for the limits.

Wrong counts in one of two sets come from a stopping test that reads one mask only; places repeated or missed come from doubling only the first place or only the step; a slowdown of 2 times comes from a condition around each place's arithmetic, and computing both places while stopping only the count avoids it; and a second place that is correct but no faster means the float begins already fill the wait with one set of 32 threads per scheduler.

Without code, two independent pieces of work inside one thread can overlap only where the processor would otherwise wait. The laptop's CPU had plenty of waiting to fill, and the laptop's GPU, with one set of 32 threads per scheduler, was already busy beginning instructions, so a second piece of work mostly added work. An optimization that removes waiting helps only where waiting exists, so where the time goes has to be found before the optimization is chosen.

The guess at the top has its answer: about 230 ms, the second version's 230.89 to 232.01 ms against 207 to 223 ms for the baseline.

A harder question to finish with. On the course GPU a 32-thread multiply-add begins in 1 cycle instead of 2. Redo the begin count for it and predict what a second place per thread would save there.

CHECK

A single set costs the larger of 9 and 16, 16 cycles per repetition, and two sets the larger of 18 and 16, 18, so 9 per set: a saving of (16 - 9) / 16 = 44 percent, against 0 percent on the laptop. Twice the float circuits per scheduler leave waiting to fill, so the same code gains on that GPU and not on this one.

The lab pages which line waits for which line, when the fat while loop stops and a second place per thread work these numbers out at length, and the notes on independent chains and filling the 4-cycle wait hold the short versions.
