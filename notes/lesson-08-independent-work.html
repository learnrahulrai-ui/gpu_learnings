The story

Part 1 of Lab 2 asks each loop to carry several independent sets of places at once, so that while one set waits for a result, another can compute. On the CPU a set is one more vector of 8 places; on the GPU it is one more place per thread.

The learner hit three walls: which line actually waits for which, how a loop carrying two sets knows when to stop, and why giving each GPU thread a second place first made the program twice as slow, then no faster at all.

When does a second independent set fill waiting time, and when is there no waiting left to fill?

Guess first

On the GTX 1650 the Lab 2 GPU baseline, one block of 32 threads, took about 208 ms. Guess the time with two places per thread, in a correct version: about 104 ms, about 160 ms, or about 230 ms?

L04 DO GPU, one set of places per thread: cycles to begin its 9 FP32 instructions = 9 x 2 = ____ , against ____ cycles along the chain. Read the code in English, line by line

  1. while (iter < max_iters) {Repeat the lines in braces as long as iter is below max_iters.
  2. maskA = (x2A + y2A <= 4) maskB = (x2B + y2B <= 4)Written in short form, not real C++: compare set A's x2 plus y2 with 4 at each index, and the same for set B.
  3. /* stopping test: ____ (not decided yet) */A blank for the rule that decides when to leave the loop. Deciding it is the exercise.
  4. itersA = itersA - maskA itersB = itersB - maskBShort form: subtract each set's mask from that set's counters, index by index.
  5. lines A..F on set A lines A..F on set BShort form: lines A to F for set A, and lines A to F for set B, in the same repetition.
  6. ++iter;Add 1 to iter.
  7. }End of the block opened by the matching brace above.

Connect the numbers

L16 DO Collect L02 (16-cycle chain), L04 (GPU: 18 cycles of begins, no saving), L06 (CPU: 2.7 sets fill the wait), L09 (1.85, not 2), L13 (2.2 times slower, then 1.11), L14 (1.79 baseline repetitions per version 2 repetition). Write one sentence: what single comparison decides whether a second independent set inside a thread helps? from: L02, L04, L06, L09, L13, L14

CHECK 
Compare the time along the chain with the time to begin all the instructions of one set: a
second set fills only the difference. On the CPU core the chain (12 cycles) is far longer than
the begins (4.5), so sets help; on the GPU with one set of 32 threads per scheduler the begins
(18) already exceed the chain (16), so the second place mostly adds work.

Tempting answer that fails: "32 threads on 32 places are 32 independent chains, so the wait is
already hidden". They are 32 sets of data on ONE instruction stream: when that instruction waits,
all 32 wait; only another instruction can fill the wait.

When it goes wrong

  • A loop with two sets gives wrong counts in one set. The stopping test reads one mask only (L08).
  • A second place per thread repeats or misses places. Only the first place or only the step was doubled (L11).
  • A second place per thread made the GPU 2 times slower. A condition around each place's arithmetic turned half the loop into control (L12, L13). Compute both places every repetition and stop only the count.
  • A second place per thread is correct but no faster. The FP32 begins already fill the wait with one set of 32 threads per scheduler (L04, L14).

In plain words

Inside one thread, two independent pieces of work can overlap only where the processor would otherwise wait. The laptop's CPU had plenty of waiting to fill; the laptop's GPU, with one set of 32 threads per scheduler, was already busy beginning instructions, so a second piece of work mostly added work.

For a manager: an optimization that removes waiting helps only where waiting exists. Find out where the time goes before choosing it.

CHECK

GPU and not on this one, because twice the FP32 units per scheduler leave waiting to fill.
