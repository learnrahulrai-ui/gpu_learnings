What sits between two clock reads

Topics: measuring. A single idea, with a few lines to calculate. Each line uses only the lines above it, and the grey note names its source. Fill every ____ on paper, then open CHECK. Any unfamiliar word: words used on this site.

The idea

The Lab 2 prelab times multiply-adds by reading the GPU's cycle counter before and after them. The compiler is free to move an instruction across a clock read when nothing ties the two together, so the order in the source code is not necessarily the order on the chip.

The question here: what actually lies between the two reads, and how can it be pinned?

Work it out

L01 The Lab 2 starter fma_latency.cu reads the clock with asm volatile("mov.u64 %0, %%clock64;" : "=l"(ret)); In English: copy the GPU's 64-bit cycle counter into ret; the part after the colon lists one output and no input. from: Lab 2 starter code

L02 Your interleaved kernel copies *n from DRAM, the memory chips outside the GPU chip, into a register that both x and y begin from, then does x = x + 3.0f; y = y + 4.0f;, then reads the clock. Hardware fact: the chip begins the instruction after a load without waiting; an instruction that reads the loaded register is held until the value arrives. So the adds are there to pay the wait for the load before the first clock read. from: your code, Jia et al. 2019, Dissecting the NVIDIA Turing T4 GPU

L03 Your machine listing (cuobjdump -sass) showed the start clock read (CS2R at 0060) before both FADD instructions (0080, 0090) that read the loaded register (written by LDG at 0020). from: your listing

L04 DO From L03, which waits now fall inside the timed window? ____ . What in L01 allowed the move? ____ . Fix: a clock read that lists x and y as inputs. If only x is listed, which add may still move inside? ____ . from: L01, L02, L03

CHECK 
inside: the wait for the DRAM load, plus the two FADDs themselves
allowed by: L01's clock read has no input, so nothing ties it to the adds
only x listed: the add on y is tied to nothing and may move after the read
(your report showed exactly this)

L05 DO End clock read with no input: can it begin before the last multiply-add of the chain has its value? ____ . Then the printed cycles are too ____ (small or large). from: L01, L02

CHECK 
yes: it reads no register that the last multiply-add writes, so nothing holds it
too small: the wait for the last value is left out

Both reads take the chain's final values as inputs. Only the machine listing shows what is timed;
the source code showed the add above the clock read in every version.
