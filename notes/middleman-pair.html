The middleman pair (cx, cy)

Topics: the picture. A single idea, with a few lines to calculate. Each line uses only the lines above it, and the grey note names its source. Fill every ____ on paper, then open CHECK. Any unfamiliar word: words used on this site.

The idea

The Mandelbrot labs fill a sheet of whole numbers, one for each place (i, j), with i counting down and j counting right. The learner called that sheet the image paper. The loop that makes each number never reads i or j: it works on two fractions, cx and cy, computed from them. They mark a point on a second sheet with (0, 0) at its center, the graph paper. The learner named (cx, cy) the middleman pair.

The question here: when the picture gets more places, does it show more of the graph paper, or the same part in finer steps?

Work it out

L01 The Lab 1 file mandelbrot_cpu.cpp computes, for the place (i, j): float cx = (float(j) / float(img_size)) * 2.5f - 2.0f; and float cy = (float(i) / float(img_size)) * 2.5f - 1.25f; In English: divide j by img_size, multiply by 2.5 and subtract 2.0 to get cx; do the same with i and subtract 1.25 to get cy. from: Lab 1 starter code

L02 Your machine printed: image size 256x256, 1000 max iterations. So img_size = 256, and i and j each go from 0 to 255. from: your output

L03 DO Place (64, 64): cx = 64 / 256 x 2.5 - 2.0 = ____ , cy = ____ . The same place with img_size = 512: cx = ____ , cy = ____ . Which place at 512 gives the pair that (64, 64) gave at 256? ____ . from: L01, L02

CHECK 
256: 64 / 256 = 0.25, x 2.5 = 0.625 -> cx = 0.625 - 2.0 = -1.375, cy = 0.625 - 1.25 = -0.625
512: 64 / 512 = 0.125, x 2.5 = 0.3125 -> cx = -1.6875, cy = -0.9375
(128, 128) at 512: 128 / 512 = 0.25 -> (-1.375, -0.625), the pair that (64, 64) gave at 256

L04 DO Smallest cx (j = 0) at either size = ____ . Largest cx at 256 (j = 255) = ____ . Largest at 512 (j = 511) = ____ . The value that j / img_size never reaches = ____ , so cx never reaches ____ . from: L01, L02

CHECK 
j = 0: cx = -2.0 at both sizes
j = 255 at 256: 255 / 256 = 0.99609375, x 2.5 = 2.490234375, - 2.0 = 0.490234375
j = 511 at 512: 511 / 512 = 0.998046875, x 2.5 = 2.4951171875, - 2.0 = 0.4951171875
j / img_size never reaches 1, so cx never reaches 1 x 2.5 - 2.0 = 0.5

img_size changes how many pairs are taken between -2.0 and 0.5, and how close together they sit.
It never changes which part of the graph paper is covered: that comes only from 2.5, 2.0 and 1.25,
typed into L01. A bigger picture is the same part in finer steps.
