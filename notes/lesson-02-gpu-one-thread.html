Lesson 2. The picture on one GPU thread

This lesson covers Lab 1, part 1, on the GPU, where you write mandelbrot_gpu_scalar and launch_mandelbrot_gpu_scalar. It needs an NVIDIA GPU and the Lab 1 folder compiled. Paragraphs with a red rule beside them are for your pencil; work each one before opening its CHECK.

The first GPU task of Lab 1 moves the reference loop onto the GPU unchanged, executed by a single GPU thread. It needs a pair of functions: the kernel, which executes on the GPU, and the launch function, which executes on the CPU and starts the kernel. The result surprises most people, because a graphics card with hundreds of arithmetic circuits, given the whole picture, takes several times longer than one CPU core, and the Fall 2025 handout's first question asks for exactly that comparison and its causes. What does one GPU thread have, compared with one CPU core, and which measured number shows it?

The question underneath it, in the words of the owner of the laptop, is what the step from definitions to a working kernel consists of:

"I know what is GPU and I know what is threadIdx ... But what is the exact intellectual step I have to do?" / "any idiot can say we will put all the things in parallel because they all work on the GPU"

Write a guess. On one CPU core the 256 by 256 picture took 61.6 ms. How long does one GPU thread on the GTX 1650 take for the same loop: less, about the same, or more? Write a number.

A kernel is started from the CPU and writes into the graphics card's memory

__global__ void mandelbrot_gpu_scalar(
    uint32_t img_size,
    uint32_t max_iters,
    uint32_t *out /* pointer to GPU memory */
) {
    /* your (GPU) code here... */
}

void launch_mandelbrot_gpu_scalar(
    uint32_t img_size,
    uint32_t max_iters,
    uint32_t *out /* pointer to GPU memory */
) {
    /* your (CPU) code here... */
}

These are the two empty functions of the GPU starter. The first begins with __global__, which marks a kernel, a function that executes on the GPU and hands nothing back; it receives the picture size, the cap on repetitions, and out, an address in the graphics card's memory, and its body is left for you. The second is an ordinary function that executes on the CPU, receives the same three values, and is meant to start the kernel.

A kernel is started from the CPU with kernel<<<B, T>>>(arguments), which, as NVIDIA's CUDA programming guide defines it, makes B blocks of T threads, every thread executing the whole kernel. The address out points to memory on the graphics card, reserved by main with cudaMalloc; the CPU cannot read it directly, which is why main copies it back with cudaMemcpy before the check. What you write follows from that: the kernel body is the reference loop nest unchanged, both for loops, cx and cy, the while loop and the store to out[i * img_size + j], and the launch function makes one block of one thread, <<<1, 1>>>, passing its three arguments on.

Compile and execute as in the setup lesson, nvcc with your -arch, and write the difference printed for mandelbrot_gpu_scalar. What does about 0.248 mean here, and what does a value between 0 and 0.248 mean?

CHECK

A correct port prints exactly 0. About 0.248 means the kernel wrote nothing: the launch line is missing, or the kernel never executed.

A value between the two means some places are wrong, and a constant typed as 2.5, a double, instead of 2.5f is enough to cause it, because it changes the rounding of cx at many places.

A single GPU thread took 403 ms, 6.55 times one CPU core

Measured on the laptop for the 256 by 256 picture at max_iters 1000, the CPU reference on one core took 61.6 ms and the GPU with one thread, <<<1, 1>>>, took 403.435 ms.

Divide 403.435 by 61.6. Then divide each time by the 16,274,722 repetitions of this picture to get the time of one repetition on each chip.

CHECK 
403.435 / 61.6 = 6.55 times slower
CPU: 61.6 ms / 16,274,722 = 3.79 ns per repetition
GPU: 403.435 ms / 16,274,722 = 24.79 ns per repetition

A chain of 5 operations explains the CPU's time and half of the GPU's

Inside one repetition some lines need the value of the line before them, and a list of such operations, each waiting for the previous one, is a chain. In the reference, the longest chain from one repetition into the next has 5 operations: w - x2, then - y2, then + cy, which make line B, then z = x + y, then w = z times z, whose w the next repetition needs first.

Published figures give the wait at each operation of the chain. For the laptop's CPU, whose cores are of the design AMD calls Zen 2, Agner Fog's instruction tables give a wait of 3 cycles for an add or multiply that needs the previous result, and AMD's specification of the Ryzen 5 4600H gives one busy core up to 4.0 billion cycles per second. On the GTX 1650 the same wait is 4 cycles, as the Lab 2 prelab measures on this very GPU; its clock during these measurements was not recorded, so this lesson assumes 1.5 billion cycles per second, and nvidia-smi -q -d CLOCK reads yours.

Work out the chain's time per repetition on each chip, 5 x 3 cycles at 4.0 billion per second and 5 x 4 cycles at 1.5 billion per second, and set each beside the measured 3.79 and 24.79 ns. Which chip does the chain alone explain?

CHECK 
CPU: 15 cycles / 4.0e9 = 3.75 ns, measured 3.79 ns
GPU: 20 cycles / 1.5e9 = 13.3 ns, measured 24.79 ns

The chain explains nearly all of the CPU's time and about half of the GPU's. The CPU core guesses which way the loop's branch goes and works ahead, so the check and the count overlap the chain. A single GPU thread executes its instructions in order and waits for the branch before the next repetition begins, so the compare and the branch add to the chain.

A single GPU thread uses 1 of the chip's 896 arithmetic circuits

NVIDIA's specification of the GTX 1650 lists 896 circuits that each do a float multiply-add for one thread, which it calls CUDA cores, and a single thread can use one of them at a time. Together with the numbers above, one GPU thread is 6.55 times slower than one CPU core, its repetition takes 24.79 ns against 3.79, and the 5-operation chain explains the CPU's time and only half of the GPU's.

Write one sentence that answers the lab's first question: what makes one GPU thread slower than one CPU core, and what does that say about how a GPU has to be used?

CHECK

A single GPU thread is a slow, simple processor, with a lower clock, no working ahead past the loop's branch, the same 5-operation chain to wait through, and 1 of 896 arithmetic circuits; a GPU is fast only when thousands of threads keep those circuits busy at once.

The reading "GPUs are slower than CPUs" fails, because the comparison sets 1 of 896 circuits against a whole core and says nothing about the chip.

The handout's first question asks how the scalar GPU version's time compares with the scalar CPU version's and what might explain each, and the three parts of the answer are above: the ratio of 6.55, the two times per repetition, and the chain calculation on each chip. A time of your own far from 403 ms points to a different GPU or clock, and the comparison that still holds is your time per repetition against the chain calculation at your clock.

Without code, a graphics card is not one fast processor but hundreds of slow, simple ones that are fast together, so moving work onto it without splitting the work into many independent pieces makes it slower, and the hardware alone buys nothing.

The guess at the top has its answer: more, 403.435 ms, which is 6.55 times the 61.6 ms of one CPU core.

A harder question to finish with. The CPU's time per repetition matches its chain calculation within about 1 percent, and the GPU thread's does not. Name a measurement that would tell whether the missing half on the GPU comes from the clock or from the instructions outside the chain.

CHECK

Fix the clock first: read it during the measurement with nvidia-smi -q -d CLOCK, or compare differences of clock64() inside the kernel with wall time. Then count cycles per repetition directly, by reading clock64() before and after the while loop for one place with a known count, 1000 for example, and dividing by that count. The excess over 20 cycles is the instructions outside the chain; a lower clock shows only in the first measurement.

Page 00 of the lab pages, what a GPU is, measured on one laptop, and page 07, which line waits for which line, work these numbers out at length, and the notes on the block of hardware a GPU chip is built from and on independent chains inside one thread hold the short versions.
