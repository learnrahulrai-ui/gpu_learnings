The story

The first GPU task of Lab 1 is to move the reference loop onto the GPU unchanged, executed by a single GPU thread. It needs two functions: the kernel, which executes on the GPU, and the launch function, which executes on the CPU and starts the kernel.

The result surprises most people. A graphics card with hundreds of arithmetic circuits, given the whole picture, takes several times longer than one CPU core. The lab's first question asks for exactly this comparison and for the reasons behind it.

What does one GPU thread have, compared with one CPU core, and which measured number shows it?

Guess first

On one CPU core the 256 by 256 picture took 61.6 ms. Guess the time for one GPU thread on the GTX 1650 doing the same loop: shorter, about the same, or longer? Write a number.

L02 CUDA facts: a kernel is started from the CPU with kernel<<<B, T>>>(arguments), which makes B blocks of T threads, every thread executing the whole kernel. out points to memory on the graphics card, allocated by main with cudaMalloc; the CPU cannot read it directly, which is why main copies it back with cudaMemcpy before the check. from: CUDA programming guide, Lab 1 starter code (main)

Measure it

L05 Measured on the laptop, 256 by 256, max_iters 1000: CPU reference on one core 61.6 ms; GPU, one thread (<<<1, 1>>>) 403.435 ms. from: your output

L06 DO 403.435 / 61.6 = ____ times slower. Per repetition, using the 16,274,722 repetitions of this picture: CPU = 61.6 ms / 16,274,722 = ____ ns; GPU = 403.435 ms / 16,274,722 = ____ ns. from: L05, computation on the lab code

CHECK 
6.55 times slower
CPU: 3.79 ns per repetition; one GPU thread: 24.79 ns per repetition

L07 Inside one repetition some lines need the value of the line before; such a list is a chain. In the reference, the longest chain from one repetition into the next is 5 operations: w - x2, then - y2, then + cy (line B), then z = x + y (line E), then w = z times z (line F), whose w the next repetition needs first. from: reference code (lines B, E, F)

L08 Published figures, used as a model: on the laptop's CPU (Zen 2 cores) an add or multiply that needs the previous result waits 3 cycles, and one busy core reaches up to 4.0 billion cycles per second. On the GTX 1650 it waits 4 cycles (measured on this GPU in the Lab 2 prelab); this lesson assumes 1.5 billion cycles per second for the laptop GPU, so read yours with nvidia-smi -q -d CLOCK. from: Agner Fog's instruction tables (Zen 2), AMD Ryzen 5 4600H specification, your output (Lab 2 prelab), assumption

L09 DO Chain time per repetition: CPU = 5 x 3 / 4.0 billion = ____ ns; GPU = 5 x 4 / 1.5 billion = ____ ns. Measured (L06): CPU ____ ns, GPU ____ ns. Which chip does the chain alone explain? ____ . from: L06, L07, L08

CHECK 
CPU: 15 cycles / 4.0e9 = 3.75 ns, measured 3.79 ns: the chain explains nearly all of it
GPU: 20 cycles / 1.5e9 = 13.3 ns, measured 24.79 ns: the chain explains about half
The CPU core guesses the loop's branch and works ahead, so the check and the count overlap the
chain. One GPU thread executes its instructions in order and waits for the branch before the
next repetition begins, so the compare and the branch add to the chain.

Connect the numbers

L10 DO Collect L05 (6.55 times slower), L06 (3.79 and 24.79 ns per repetition), L09 (the chain explains the CPU, half of the GPU), and the fact that the GTX 1650 has 896 FP32 units while one thread can use one of them at a time. Write one sentence answering the lab's first question: what makes one GPU thread slower than one CPU core, and what does that say about how a GPU must be used? from: L05, L06, L09, NVIDIA Turing specification

CHECK 
One GPU thread is a slow, simple processor: a lower clock (L08), no working ahead past the
loop's branch (L09), the same 5-step chain to wait through, and 1 of 896 FP32 units.
A GPU is fast only when thousands of threads keep those units busy at once.

Tempting answer that fails: "GPUs are slower than CPUs". The comparison is 1 of 896 units
against a whole core, so it says nothing about the chip.

When it goes wrong

  • Difference about 0.248 and a tiny time. The launch line is missing or the kernel never executed (L04).
  • A difference between 0 and 0.248. A line differs from the reference; a double constant such as 2.5 instead of 2.5f is enough (L04).
  • Your GPU time is far from 403 ms. A different GPU or clock. Compare your time per repetition with the chain model for your own clock (L08, L09).

In plain words

A graphics card is not one fast processor: it is hundreds of slow, simple ones that are fast together. Given to a single thread, the whole picture takes more than six times longer than on one ordinary CPU core.

For a manager: moving work onto a GPU without splitting it into many independent pieces makes it slower, not faster. The hardware purchase alone buys nothing.

The interviewer's next question

Your CPU's time per repetition matches its chain model within about 1 percent; the GPU thread's does not. Name a measurement that would tell whether the missing half on the GPU comes from the clock or from the instructions outside the chain.

CHECK 
Fix the clock first: read it during the measurement (nvidia-smi -q -d CLOCK), or compare
clock64() differences inside the kernel with wall time. Then count cycles per repetition
directly: read clock64() before and after the while loop for one place with a known iters
(1000, for example) and divide by the iters. The excess over 20 cycles is instructions outside
the chain; a lower clock shows up only in the first measurement.
