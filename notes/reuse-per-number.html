Reuse per number fetched, and the side of a tile

Topics: Lab 4, memory. A single idea, with a few lines to calculate. Each line uses only the lines above it, and the grey note names its source. Fill every ____ on paper, then open CHECK. Any unfamiliar word: words used on this site.

The idea

A block that computes a square tile of a matrix product copies pieces of the inputs into on-chip memory and uses every copied number several times. Named numbers such as BM = 64 fix the side of that tile, and a number kept out of habit cannot be changed safely.

The question here: what decides the smallest useful side of the tile, and what stops it from growing?

Work it out

L01 The Lab 4 handout's numbers for the course GPU: 26.7 TFLOP/s of multiply-adds, 2 FLOP each; the L2 cache 2.4 TB/s; the L1 memory of all 48 SMs, the identical blocks of hardware the chip is built from, 13.4 TB/s; the second kernel must finish the 3072 by 3072 by 3072 test in under 8 ms. From the formula of the product: a block computing a BM by BN tile of C fetches, at one value of k, BM + BN numbers for BM * BN multiply-adds. from: the Lab 4 handout; the starter's CPU reference

L02 DO Numbers fetched from L2 per multiply-add for 32 by 32 tiles ____ , for 64 by 64 ____ . L2 time over the 3072 test: ____ ms and ____ ms, against ____ ms of multiply-adds. from: L01

CHECK 
1/16 and 1/32
3.02 ms and 1.51 ms, against 57,982,058,496 FLOP / 26.7 TFLOP/s = 2.17 ms
only 64 by 64 leaves the multiply-adds to set the time

L03 DO Solve for the side T of a square tile at which L2 time equals multiply-add time: ____ . Does 3,072 appear in the answer? ____ . from: L01, L02

CHECK 
8 / (T * 2.4) = 2 / 26.7, so T = 4 * 26.7 / 2.4 = 44.5
no: the number of multiply-adds cancels; the side depends only on the chip's two rates,
and 64 is the first power of 2 above it

L04 DO Each thread computing a 4 by 4 patch of C in registers reads ____ numbers from shared memory per ____ multiply-adds; time at 13.4 TB/s: ____ ms, against 8. With one number of C per thread: ____ ms. from: L01

CHECK 
8 reads per 16 multiply-adds, 1/2 each: 58.0 GB, 4.33 ms, under 8 ms
one number per thread: 2 reads per multiply-add, 231.9 GB, 17.3 ms
