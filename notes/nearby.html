Nearby: 32 stores in 4 blocks of 32 bytes

Topics: GPU chip, memory. A single idea, with a few lines to calculate. Each line uses only the lines above it, and the grey note names its source. Fill every ____ on paper, then open CHECK. Any unfamiliar word: words used on this site.

The idea

In Lab 1's GPU version, thread t takes the places j = t, t + 32, t + 64, and so on. Inside one thread those places are 32 apart, which is why the learner refused the claim that the memory access is "nearby". The threads, however, store at the same moment, and memory receives the 32 stores of one instruction together.

The question here: which counts settle it, and what would a different split of places cost?

Work it out

L01 Your kernel: for each i, thread t (0 to 31) takes j = t + 32 x k for k = 0 to 7 and stores its iters at out[i * 256 + j]. Each value is a 4-byte whole number, so its byte number is 4 x (i x 256 + j). from: your code

L02 NVIDIA facts: the store executes for all 32 threads together, with the same i and k. Memory moves bytes in blocks of 32 bytes that begin at a multiple of 32. The profiler calls one store instruction for the 32 threads a request, and each 32-byte block it touches a sector. from: CUDA programming guide, Nsight Compute metric names

L03 DO i = 0, k = 0: thread 0 stores bytes 0 to 3; thread 31 stores bytes ____ to ____ . Blocks of 32 bytes touched = ____ . Store instructions for the whole picture = 256 x 8 = ____ . Blocks touched = ____ . Your profiler printed 2,048 requests and 8,192 sectors. from: L01, L02, your output

CHECK 
thread 31: j = 31, bytes 124 to 127
bytes 0 to 127 = 4 blocks of 32
2,048 store instructions (requests), 2,048 x 4 = 8,192 blocks (sectors): both match the profiler

L04 DO Another split: thread t takes j = 8t to 8t + 7. First store, i = 0: thread t stores at byte ____ . Thread 0 at ____ , thread 1 at ____ , thread 31 at ____ . Blocks of 32 bytes touched by this one store instruction = ____ . For the whole picture = 2,048 x ____ = ____ , which is ____ times L03. from: L01, L02, L03

CHECK 
thread t stores j = 8t, byte 32t: 0, 32, ..., 992
each in its own 32-byte block: 32 blocks per store instruction
2,048 x 32 = 65,536 blocks, 8 times L03's 8,192

Inside one thread the places are 32 apart; across the 32 threads of one store they sit side by side.
Both are true; memory receives only the second.
