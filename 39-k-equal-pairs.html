39. Tensor cores: why only pairs with the same k, and what a layout must guarantee

Each line uses only what the lines above it made. The grey note says which line it takes from. Fill every ____ on paper, then open CHECK. Under each piece of code, a panel reads it in English line by line. Any unfamiliar word: words used on this site.

The story

A step-by-step text on tensor cores, which the learner was reading, split the products of two matrices into two kinds: products whose two numbers share the same k, and products whose numbers do not. Then it said that a tensor core instruction never reads k at all, and that its layouts keep k-equal numbers next to each other.

The learner rejected the whole distinction. Everyone multiplies matching numbers and adds them, so why name the products that are never made? And how could a layout have anything to do with k, when k belongs to the matrices and a register holds whatever numbers the program puts in it?

Why does a matrix product need the k-equal pairs to be named at all, and what does a register's layout have to do with them?

Write one sentence on why k-equal pairs are named. from: L02, L03, L05, L06, L08, L09

CHECK 
They are named because the hardware multiplies places, not meanings: of the 64 possible
pairings of a result's numbers only 8 are k-equal, and the only thing that makes the
instruction pick those 8 is the layout, which puts the same k in the same place of A's
registers and of B's, the same t for 32-bit numbers and the same neighbouring pair for 16-bit
ones.

Tempting answer that fails: "everyone knows to multiply matching numbers, so naming them is
pointless". The instruction does not know which numbers match: a layout that puts k-unequal
numbers in paired places computes a wrong product without any error (L09).

In plain words

In a matrix product, each number of the result uses only the pairs whose shared index agrees, a small part of all the pairs one could form. People do this without noticing; the hardware cannot notice anything, so the way the numbers are laid out in its storage must place every matching pair together and no other pair. Naming the matching pairs is naming what the layout has to guarantee.

For a manager: when hardware does the pairing blindly, correctness lives in the data's arrangement; ask what the arrangement guarantees, not only what the arithmetic does.

The interviewer's next question

With 8-bit numbers a 32-bit register holds 4 of them. NVIDIA's PTX manual places A of the 8-bit instruction m16n8k32 so that thread n's first register holds A(g, 4t) to A(g, 4t + 3). If those 4 numbers are converted to 16 bits for the instruction m16n8k16, which threads must hold them?

CHECK 
The 16-bit placement puts k = 2t' and 2t' + 1 in thread t' of a set (L07). The 8-bit thread t
holds k = 4t to 4t + 3: k = 4t and 4t + 1 belong to the 16-bit thread t' = 2t, and k = 4t + 2
and 4t + 3 to t' = 2t + 1. Half of the numbers must move to another thread, and a conversion
of each number's format moves nothing between threads.
