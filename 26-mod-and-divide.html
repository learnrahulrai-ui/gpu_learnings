26. Lecture 3: which memory chip holds an address, mod and divide

Each line uses only what the lines above it made. The grey note says which line it takes from. Fill every ____ on paper, then open CHECK. Under each piece of code, a panel reads it in English line by line. Any unfamiliar word: words used on this site.

The story

Lecture 3 of MIT 6.S894 is about memory. It begins with the course GPU's own numbers: data crosses from the CPU at 32 GB/s, from the graphics card's memory chips at 360 GB/s, from the L2 cache at about 2.5 TB/s, and the chip's 6144 execution units can begin 13.4 trillion instructions a second. Then it explains where the 360 comes from: not from one fast chip, but from several ordinary chips placed side by side, each with its own connection.

That raises a question the slides answer with two drawings. A program sees one long list of addresses; the memory is several separate chips. Which chip holds which address? In the first drawing each chip holds one long unbroken piece of the list; in the second the chips take turns, a small piece each. The lecturer described the two rules as divide and mod, and that is where the learner stopped.

Both rules give every address exactly one home. Does it matter which one the hardware uses?

L05 The slides then ask which chip holds which address, with 8 GDDR6 chips of 4 GB in the drawing. First drawing: the first 4 GB of addresses go to the first chip, the next 4 GB to the second, and so on; the chip number is the address divided by 4 GB, rounded down. Second drawing: the chips take turns, one small piece of addresses each, over and over; the chip number is the address divided by the size of a piece, rounded down, then taken mod the number of chips (the remainder after dividing by it). The slides call the second striping, and do not give the size of a piece. from: the Lecture 3 slides "Mapping address space to memory channels"

L06 Then: an EU takes in 32 bits per cycle; the 32 EUs under one instruction take in 32 x 32 = 1024 bits = 128 bytes per cycle, of neighbouring elements i, i + 1, i + 2, and so on. from: the Lecture 3 slides

L09 DO The course GPU has 5 chips. With the mod rule and pieces of 4 bytes, float k of the 128 bytes goes to chip k mod 5. Floats on each chip: ____ . The instruction is done when its last float arrives, so the time is set by ____ : ____ transfer times, which is ____ times sooner than the 32 of the divide rule. from: L04, L05, L07

CHECK 
chips 0 and 1: 7 floats each (k = 0, 5, ..., 30 and k = 1, 6, ..., 31); chips 2, 3, 4: 6 each
the busiest chip sets the time: 7 transfer times; 32 / 7 = 4.6 times sooner
not 5 times: 32 floats do not split evenly over 5 chips

L10 Which part of the address chooses the chip? With the divide rule the chip number changes only when the address crosses a 4 GB boundary, so it is decided by the top part of the address. With the mod rule it changes at every piece, so it is decided by the bottom part. Neighbouring addresses differ only in their bottom part. from: L05

CHECK

40 x 128 = 5,120 bytes = 20 pieces = 4 pieces on each of the 5 chips
with pieces bigger than one instruction's bytes, the mod rule spreads a stream of
instructions over all chips, not a single instruction

CHECK 
Programs read neighbouring addresses, and neighbouring addresses differ only in their bottom
part; dealing addresses out by that bottom part (mod) sends neighbouring addresses to
different chips, which is the only way a program reading in order keeps all chips busy and
reaches the 360 GB/s that exists only with every chip delivering at once.
An instruction is done when its last piece arrives, so the busiest chip sets the time
(7 transfers, not 32 / 5 = 6.4, on the course GPU's 5 chips).

Tempting answer that fails: "the GPU has 360 GB/s, so any order of reading gets 360 GB/s".
Under the divide rule one instruction's 128 bytes come from one chip in 32 transfers (L07),
at one chip's 72 GB/s.

In plain words

A graphics card's memory is several chips working side by side, and its quoted speed is the sum of all of them working at once. Addresses are dealt out to the chips in small turns, so that a program reading neighbouring data keeps every chip busy. Dealt out in large blocks instead, neighbouring data would all sit in one chip, and the program would get one chip's speed.

For a manager: a memory system's quoted speed assumes the work keeps every chip busy at once; ask whether your data is read in an order that does.

The interviewer's next question

With the mod rule over 5 chips and pieces of 4 bytes, the 32 threads of one instruction read floats 0, 5, 10, ..., 155 (each 5 floats from the next). How many chips serve the instruction, and what does that say about steps between reads?

CHECK 
Float 5k goes to chip 5k mod 5 = 0 for every k: all 32 floats on chip 0, 32 transfers,
as slow as the divide rule. A step that is a multiple of the number of chips sends every
read to the same chip and undoes the mod rule. The slides do not say whether the course
GPU scrambles its choice of chip to avoid this; a measurement that reads with different
steps and times each one would show it.
