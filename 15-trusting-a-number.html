Each line uses only what the lines above it made. The grey note says which line it takes from. Fill every ____ on paper, then open CHECK. Under each piece of code, a panel reads it in English line by line. Any unfamiliar word: words used on this site.

The story

For every version of the Lab 2 picture, the starter program prints two numbers: an "average output difference from reference" and a time in milliseconds. Every speedup in the write-up is built from these. A speedup claim is only honest if both versions computed the same picture and were timed the same way.

The learner once put it as an interviewer would: they do not want guesswork, they want proof of where the time goes. The same standard applies to correctness. A difference that prints as a tiny number looks like proof of correctness, and a time that prints as the fastest of several trials looks like proof of speed.

What exactly does each printed number compress away, and can a broken program print a smaller difference than a correct one?

In plain words

A single summary number can hide the very thing you need to know. An average error near zero can come from one serious mistake or from many harmless roundings, and the fastest of several timings says nothing about the slow ones. Before trusting "correct and twice as fast", count the wrong answers directly and time both versions the same way.

For a manager: ask how many results were wrong, not what the average error was, and ask whether both versions were timed with the same method.
