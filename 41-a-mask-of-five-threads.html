41. CUTLASS 1094: a shuffle mask that named 5 of the 32 threads executing it

The story

NVIDIA's CUTLASS library is a collection of fast matrix multiplication kernels. In September 2023 a user reported that one of its examples, which worked on an A100 GPU, failed on the newer H100 with an illegal instruction. The cause was a single number in a single line: the mask 0x1f in a warp shuffle, an instruction that copies a value from one thread's registers to other threads of the same set of 32. NVIDIA's fix replaced 0x1f with 0xffffffff, four days after the report.

The learner could not accept it. The documentation had not changed, the code had worked for years, and the shuffle only sends a value from one thread to the others, so why should any mask, let alone two of them, matter? If the rule says one thing and the hardware does another, one of them must be wrong.

What does the mask of a shuffle say, and how could wrong code give right answers on one GPU and crash on the next?

Work it out

L01 NVIDIA's CUDA programming guide: the hardware executes threads in units of 32 that NVIDIA calls warps. __shfl_sync(mask, var, srcLane) returns the value of var held by the thread of the same warp whose number in the warp is srcLane. The mask has one bit for each of the 32 threads; "Each calling thread must have its own bit set in the mask and all non-exited threads named in mask must execute the same intrinsic with the same mask, or the result is undefined." from: the CUDA programming guide, warp shuffle functions

L02 CUTLASS issue 1094, opened 14 September 2023: in examples/45_dual_gemm/kernel/dual_gemm.h, every thread of a block executes, with no if around it: from: CUTLASS issue 1094

int warp_idx = __shfl_sync(0x1f, threadIdx.x / 32, 0);

L03 The same issue: the code works correctly on an A100; on an H100 the kernel fails with cudaErrorIllegalInstruction, and the debugger cuda-gdb reports Warp Illegal Instruction with all 32 threads of warp 0 active. Pull request 1097, merged on 18 September 2023, replaced 0x1f with 0xffffffff. The maintainer's explanation: 0x1f "has five 1s", 0xffffffff "has 32 1s", and a warp "has 32 threads, so we need 32 1s." from: CUTLASS issue 1094 and pull request 1097

In plain words

A warp shuffle copies a value between the 32 threads that execute together, and its mask lists which of them take part. The code listed only 5 while all 32 took part, which the documentation calls undefined. Because the value copied was one every thread already had, the old GPU gave right answers anyway, and the mistake surfaced only when a newer GPU refused the instruction.

For a manager: code that works only because the hardware tolerates a broken rule is a delayed failure; ask whether a result is correct by rule or by luck before a hardware upgrade answers it.
