19. Lecture 2: what each register of the slide's loop holds

Each line uses only what the lines above it made. The grey note says which line it takes from. Fill every ____ on paper, then open CHECK. Under each piece of code, a panel reads it in English line by line. Any unfamiliar word: words used on this site.

The story

Lecture 2 of MIT 6.S894 opens with a loop of seven instructions for a simple processor: two loads from memory, a multiply, an add, an add of the number 4, a compare-and-jump, and a store. The lecturer read it aloud in a few seconds: it goes through two lists of numbers, multiplies each pair, and adds the products into one total.

The learner could read each instruction alone. What did not follow was the address inside the loads, mem[r0+r2]: why add two registers to say where to read, whether mem is an array, and how anyone can tell from the code that r0 must be a large address while r2 stays a small number. Knowing what every instruction does had not said what the loop does.

The code never states the size or the purpose of any register. Which facts in seven instructions decide what each register holds?

Read the code in English, line by line

  1. ld r3, mem[r0+r2]Add the numbers in r0 and r2; the sum is an address. Read the value stored at that address in memory and put it in r3.
  2. ld r4, mem[r1+r2]The same with r1 and r2; the value goes into r4.
  3. mul r3, r3, r4Multiply r3 by r4 and put the product in r3.
  4. add r5, r5, r3Add r3 to r5 and put the sum in r5.
  5. addi r2, r2, 4Add the number 4, written inside the instruction (the i of addi), to r2 and put the sum in r2.
  6. blt r2, $400, LOOPIf r2 is less than 400, jump to the instruction named LOOP; otherwise go on to the next one. blt stands for branch if less than.
  7. st addr[r6], r5Store the value in r5 into memory, at the address held in r6.
  8. ...More instructions follow on the slide; they are not shown.

8-byte values: 1000..1007 and 1004..1011 share 1004..1007, so each read would take half of
one value and half of the next, which is no value the program stored

So the 4 in addi is the size of one value. r2 does not count iterations; it says how many
bytes into each list the current iteration reads: 4 * (k - 1) in iteration k.

A register's role comes from how the loop treats it, not from how big its number is:
never written: a fixed address (r0, r1, r6); increased by a fixed step and compared with a
limit: how far into the lists (r2); refilled before each read: this iteration's value
(r3, r4); added to itself: the total (r5).

Tempting answer that fails: "r0 and r1 are addresses because they are big, and r2 is a
count because it is small". The code never says how big r0 is (L05 had to assume it), and
r2 is not a count: it reaches 396 in iteration 100, because the step 4 is the size of one
value (L07).

In plain words

A short loop can be read without knowing any of its numbers. For each storage place, ask whether the loop changes it and how. A place the loop never changes says where the data lives. A place that grows by a fixed step and is compared with a limit says how far through the data the loop has come. A place refilled every time holds the current item, and a place that adds to itself keeps the total.

For a manager: ask a candidate which values a loop never changes and which one it keeps adding to; the answer shows whether they read the code or only recognised its words.

The interviewer's next question

Which instructions of iteration 2 need a value that iteration 1 computed, and which need nothing from iteration 1?

CHECK 
need a value from iteration 1:
  ld r3 and ld r4   r2 = 4, written by iteration 1's addi
  addi              r2, written by iteration 1's addi
  add               r5 = 2, written by iteration 1's add
need nothing from iteration 1:
  mul               only iteration 2's two loads
  blt               only iteration 2's addi
So iteration 2's loads wait only for iteration 1's addi, not for its loads, its mul or
its add: the written order of the instructions is not the order the values need.
