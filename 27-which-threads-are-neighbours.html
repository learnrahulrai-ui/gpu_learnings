Each line uses only what the lines above it made. The grey note says which line it takes from. Fill every ____ on paper, then open CHECK. Under each piece of code, a panel reads it in English line by line. Any unfamiliar word: words used on this site.

The story

Lab 3 of MIT 6.S894 opens with two small kernels that copy the same array. Both give every thread the same amount of work; they differ only in which floats each thread takes. In the first, each thread copies one unbroken stretch of floats; in the second, a thread's floats are spread out with the other threads' floats between them. The lab asks you to time both.

The learner wrote the first kernel and could recite what every piece of it does: the thread number, the loop, the multiplication. What was missing was the step from the code to its consequence. Even with the line typed out, it was not visible which of the two cases it was, or what the threads were doing together while it executed.

From the index line alone, without executing anything, can you tell whether the floats one instruction reads sit side by side in memory?

Tempting answer that fails: "each thread reads consecutive floats, so the loads are ideal".
Consecutive within one thread is consecutive in time; the 32 floats of one instruction are
4,096 bytes apart (L07).

In plain words

The memory hands data to the 32 threads of one instruction together. If those 32 threads ask for numbers that sit side by side, a few deliveries cover all of them. If each thread walks its own distant stretch, each instruction needs a delivery per thread, even though each thread on its own reads neatly in order.

For a manager: code that looks orderly for each worker can be the worst order for the hardware; ask what the workers who move together touch at the same moment.

The interviewer's next question

The Lab 3 handout says that a pointer declared const and __restrict__ may be cached in L1. If src were declared that way, would your kernel of L03 need fewer pieces per instruction, less traffic beyond L1, or both?

CHECK 
Not fewer pieces per instruction: the 32 addresses of one instruction are the same, x apart.
What can fall is the traffic beyond L1: if L1 keeps each thread's piece until that thread's
next 7 iterations, those reads are answered without going to L2. Whether L1 keeps them
depends on how many pieces all the warps of an SM hold at once; only a measurement on your
GPU settles it.
