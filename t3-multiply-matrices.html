T3. Multiplying matrices: same arithmetic, very different times

The story

Matrix multiplication is the calculation underneath most of modern AI. It is famous as the job GPUs are best at, because it has a huge amount of arithmetic: for two square tables of 1024 by 1024 numbers, over two billion multiplications and additions.

Every GPU course then shows the same sequence of programs: a plain version where each thread computes one answer, a "tiled" version that copies small squares of the tables into fast memory inside the chip, and then faster and faster versions. People memorize the sequence. The learner of this site described exactly that trap: it is one thing to know the definition of tiling, and another to derive the need for it.

The arithmetic is identical in every version; nobody removes a single multiplication. So what is every faster version actually changing, and how far does it have to go?

Work it out

L01 Tables A, B and the answer C are n by n, stored as arrays with down-number i and right-number j at place i x n + j. The answer at (i, j) is the sum over k of A at (i, k) times B at (k, j): the A values with down-number i (a left-to-right strip of A) meet the B values with right-number j (an up-to-down strip of B). from: definition

L02 The plain program, one thread per answer (n is assumed to be a multiple of the block size): from: code

__global__ void matmul(const float *A, const float *B, float *C, int n) {
    int i = blockIdx.y * blockDim.y + threadIdx.y;
    int j = blockIdx.x * blockDim.x + threadIdx.x;
    float s = 0.0f;
    for (int k = 0; k < n; ++k)
        s += A[i * n + k] * B[k * n + j];
    C[i * n + j] = s;
}

Read the code in English, line by line

L08 Hardware fact: each SM has shared memory, storage inside the SM that all threads of a block can read many times faster than the graphics card's memory; Turing allows at most 64 KB of it per SM. Tiling: a block of T by T threads copies a T by T square of A and one of B into shared memory, and every value copied is then used by T threads instead of being read T times from memory. from: NVIDIA Turing Tuning Guide, definition

L12 DO Collect L03, L04, L05, L07, L09, L10, L11. The arithmetic never changes. Write one sentence on what every faster version changes, how far it must go, and what stops square tiles in shared memory from getting there comfortably. from: L03, L04, L05, L07, L09, L10, L11

CHECK 
Every faster version raises how many times each byte fetched from memory is used: from 0.25
operations per byte (plain) toward the 21 needed, while the matrix itself would allow 170.7.
Square tiles alone need T = 84 to get there, and at T = 84 one block takes 55 of an SM's 64 KB,
so no second block fits on the SM to cover the first one's waits. Faster versions therefore also
reuse values held in each thread's registers, not only in shared memory.

Tempting answer that fails: "matrix multiplication is arithmetic-heavy, so it is limited by the
arithmetic". L07 puts the plain program 84 times on the memory side.

In plain words

Multiplying large tables has plenty of arithmetic, but a simple program fetches the same numbers from memory over and over, and the fetching, not the arithmetic, sets the time. Each well-known speed-up is a way to fetch a number once and use it many times while it is close to the arithmetic circuits.

For a manager: when a team says a model "is compute-bound", ask for the number of operations per byte of memory traffic. Below about 21 on this card, it is not.
