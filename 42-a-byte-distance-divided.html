The story

NVIDIA Warp is a Python library that compiles Python functions into kernels for the GPU or the CPU; the name of the library has nothing to do with the 32-thread warp. Its tile functions load pieces of arrays into a block's threads, keeping the piece either in registers or in shared memory. In November 2026 Warp issue 2282 reported that the register path reads the wrong numbers from some arrays of 3-float vectors, with no error at all.

The arrays in question had padding: each vector of 3 floats was followed by an unused fourth float. The learner had only met padding inside C structures, did not expect it between the elements of an array, and could not believe that a library tested as widely as this one could hand back wrong numbers for years.

What did the library's arithmetic assume about an array, and why would no ordinary test ever break that assumption?

CHECK 
The register path changes a distance from bytes into whole elements by dividing by the element
size, which silently assumes that every element starts a multiple of its own size from the
array's start; ordinary arrays always satisfy that, so every test with them reads the right
numbers, and only a padded array, its vec3 elements 16 bytes apart, exposes reads that start
at floats 0, 3, 6 instead of 0, 4, 8, with no error.

Tempting answer that fails: "a library this widely used and tested cannot read wrong numbers".
Tests with ordinary arrays can never reach the fault, because for them the division is exact
(L07).

In plain words

The library stored where each element of an array begins as a distance in bytes, then turned that distance into a count of elements by dividing by the element's size. That is correct whenever elements sit back to back, which is almost always, so every usual test gave right answers. When elements had unused space between them, the division threw part of each distance away and the library quietly read from the wrong places.

For a manager: a check that every common case satisfies can still hide a wrong assumption; ask which inputs would break the assumption, and test those on purpose.
