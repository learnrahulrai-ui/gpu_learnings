The story

Lab 3 of MIT 6.S894 simulates a wave on a grid of cells. Each cell holds a height; at every time step, each cell's next height is computed from its own previous height and the present heights of itself and its four neighbours. The lab's first GPU version launches one kernel per step and gives every cell its own thread, and the learner wrote it by following the CPU reference in the starter code.

Copying the reference was easy. Saying why the copy is right was not. The kernel writes its results into the same array that other threads are reading during the same step; it reads cells a whole line of the grid away; it stops threads at the edge of the grid with an early return. The learner wanted what a careful reader would predict from the code, not a list of what each line does.

When thousands of threads update one grid at the same moment, what has to be true of the code for the result to be exactly the CPU's?

In plain words

Each cell's new value depends on its neighbours' current values, which are kept in a separate copy that nobody changes during the step, so all the cells can be updated at the same moment and the result is exact. A step ends only when every cell is done, and the GPU guarantees that between one launch and the next. The edge of the grid needs its own rule, because edge cells have no neighbour on one side.

For a manager: before executing work in parallel, ask who writes each piece of data and who still needs its old value in the same round; the answer decides whether the parallel version is correct, before any speed is measured.

The interviewer's next question

The handout's large test executes 12800 steps on 3201 by 3201 cells. How many kernel launches does your version make, and where must every height go between one step and the next?

CHECK 
12,800 launches, one per step (L08). Between steps every height goes back to global
memory: each step reads all of u0 and u1 from it, through the L2 cache, and writes all of
u0 back, because no step keeps heights on the chip for the next one. The handout's second
version keeps a tile of the grid in the on-chip memory of one of the chip's identical
blocks, which NVIDIA calls an SM, for several steps instead, at the price of a region of
valid cells that shrinks by one cell per step on every side.
