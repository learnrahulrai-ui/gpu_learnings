The story

Lab 6 of MIT 6.S894 replaces the multiply-adds of the earlier matrix kernels with tensor core instructions. Each such instruction multiplies a 16 by 8 matrix A by an 8 by 8 matrix B and adds a 16 by 8 matrix C, and 32 threads execute it together. The prelab asks for one such multiply, done by one block of 32 threads.

The learner began the way every earlier kernel began: give the thread a number, then split the number by 4. Both lines looked like plain arithmetic that any program could contain, with nothing to do with tensor cores. The learner asked what was new about them in this lab, and where the 4 came from, since no matrix in the program had a 4 in it.

L01 The Lab 6 handout: the instruction mma.sync.aligned.m16n8k8.row.col.f32.tf32.tf32.f32 computes D = A * B + C, with A of 16 by 8 numbers, B of 8 by 8 and C and D of 16 by 8. NVIDIA's CUDA programming guide: the hardware executes threads in units of 32 that NVIDIA calls warps, each thread with its own registers; the handout: this instruction is executed by a whole warp, its inputs and outputs spread over the registers of all 32 threads. The prelab starter launches the kernel as one block of exactly 32 threads. from: the Lab 6 handout and starter; the CUDA programming guide

L02 NVIDIA's PTX manual fixes which numbers each thread holds. For the thread whose number in its warp is n, with g = n / 4 rounded down and t = n % 4, its four A registers hold A(g, t), A(g + 8, t), A(g, t + 4) and A(g + 8, t + 4), its two B registers B(t, g) and B(t + 4, g), and its four C registers C(g, 2t), C(g, 2t + 1), C(g + 8, 2t) and C(g + 8, 2t + 1). The first number in the brackets counts down the matrix, the second across. from: NVIDIA's PTX manual, mma fragments for m16n8k8 with tf32

In plain words

In earlier GPU programs the programmer decided which thread computes which part of the result, and any fair split gave the right answer. The tensor core instruction takes that choice away: it treats each thread's storage as fixed pieces of the matrices according to the thread's place among the 32 threads that execute it together. So the program's first job is to compute that place exactly, and the numbers it uses come from the instruction, not from the data.

For a manager: when hardware fixes how work is divided, the code must follow the hardware's numbering exactly; ask where a numbering comes from before accepting that it is arbitrary.
