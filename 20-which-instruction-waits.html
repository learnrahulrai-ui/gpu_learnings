20. Lecture 2: which instruction waits for which, and how the next loads begin early

Each line uses only what the lines above it made. The grey note says which line it takes from. Fill every ____ on paper, then open CHECK. Under each piece of code, a panel reads it in English line by line. Any unfamiliar word: words used on this site.

The story

Lecture 2 of MIT 6.S894 shows how a processor can go faster on the same loop of seven instructions: it can begin more than one instruction per cycle, and it can begin an instruction before others written above it, as long as the program's result stays the same as if everything had executed in written order. The lecturer added that a value from main memory arrives hundreds of cycles after the load asks for it.

The learner accepted that the loop's two loads do not depend on each other. The thinking stopped at the loop itself: this iteration's multiply and add are still waiting for memory, so how can the processor already fetch the next iteration's values? And since the total is stored at the end, does the processor not need every earlier product before it moves on?

An iteration cannot finish until its values arrive. What, exactly, can the next iteration begin without?

Guess first

Assume each load's value arrives 200 cycles after the load begins, and the loop has 100 iterations. Strictly in written order, the processor waits for memory once per iteration. A processor that may begin any instruction whose inputs are ready: how many 200-cycle waits long is the whole loop? Write a number.

Read the code in English, line by line

  1. ld r3, mem[r0+r2]Add the numbers in r0 and r2; the sum is an address. Read the value stored at that address in memory and put it in r3.
  2. ld r4, mem[r1+r2]The same with r1 and r2; the value goes into r4.
  3. mul r3, r3, r4Multiply r3 by r4 and put the product in r3.
  4. add r5, r5, r3Add r3 to r5 and put the sum in r5.
  5. addi r2, r2, 4Add the number 4, written inside the instruction (the i of addi), to r2 and put the sum in r2.
  6. blt r2, $400, LOOPIf r2 is less than 400, jump to the instruction named LOOP; otherwise go on to the next one. blt stands for branch if less than.
  7. st addr[r6], r5Store the value in r5 into memory, at the address held in r6.
  8. ...More instructions follow on the slide; they are not shown.

In plain words

A processor waiting for memory can keep asking for the next items, as long as asking does not depend on the answer it is waiting for. In this loop, where to read next comes from a counter, never from the values read, so dozens of requests can be waiting at once and their waits overlap. The price is room to hold every answer that has not been used yet, and the bookkeeping that makes the result come out as if nothing had been reordered.

For a manager: when work waits on slow memory, ask whether the next request depends on the previous answer; if it does not, the waits can overlap, and the same hardware can finish tens of times sooner.
