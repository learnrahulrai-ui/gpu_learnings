22. Lecture 2: which loop of a matrix multiply can be split, and which cannot

The story

Lecture 2 of MIT 6.S894 returns to a matrix multiply: three loops, one inside another, over i, k and j, and in the middle a single statement that adds a product into one entry of the result C. The lecturer pointed at the innermost loop, over j, said that all of its iterations are independent of each other, rewrote it as "for all j", and drew two cores executing the same instructions, with only the loop variable different between them.

The learner asked how the lecturer could see that at a glance when they could not. Then came a second split, by i instead of j, described as a different way of dividing the matrix. So the same statement could be split by j or by i, with no visible rule for either.

What in the statement says that the iterations of a loop can execute at the same time, and is there a loop whose iterations cannot?

Guess first

In C[i*N + j] += A[i*N + k] * B[k*N + j] with N = 3, the loop over k has 3 iterations for each pair (i, j). Can those 3 iterations execute at the same time without changing C? Yes or no.

In plain words

To know whether pieces of work can be done at the same time, look at where each piece writes its result. Pieces that write to different places can go in any order, or all at once. Pieces that add into the same place must take turns, or the place ends up holding only one of their contributions.

For a manager: the question to ask about any plan to split work is whether two workers ever write the same thing; if not, the work splits, and if so, someone must combine their results, and that step costs time.

The interviewer's next question

Can the k loop be split anyway? Take one entry of C with N = 1024 and 4 cores, and say what the split costs.

CHECK 
Yes, if each core keeps its own total: core 0 adds k = 0 to 255, core 1 k = 256 to 511,
core 2 k = 512 to 767, core 3 k = 768 to 1023, each into a separate total; then the 4
totals are added, 3 more adds that must wait for all 4 cores.
Each core's chain is 256 adds instead of 1024. The cost is the 4 extra totals, the final
combining step, and a changed order of adds, so float rounding can make the last bits
differ from those of the single chain of 1024.
