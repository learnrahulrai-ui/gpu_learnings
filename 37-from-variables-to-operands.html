The story

After loading its floats, each thread of the Lab 6 prelab has to hand them to an instruction that the kernel's language does not have. The handout supplies the instruction as text, and the kernel inserts that text with an asm statement. The learner's statements first converted each float of A and B into the tensor core's TF32 format, then executed the multiply.

The syntax broke the learner's reading: percent signs followed by numbers, two colons, letters in quotes such as "=r" and "f", and an instruction name that mentioned neither the learner's variables nor any thread. It looked like two languages mixed in one line, with no rule saying which part was which.

What does each part of an asm statement do, and which part belongs to the instruction and which to the program?

Work it out

L01 NVIDIA's guide Inline PTX Assembly in CUDA: the basic form is asm("template-string" : "constraint"(output) : "constraint"(input));. The template string holds instruction text with references to the operands; each %n in it refers to the n-th operand of the lists that follow, counted in text order from 0, and the outputs are always listed before the inputs. The input operands are loaded into registers before the statement, and the result register is stored to the output after it; the "=" in "=r" marks a register that is written. from: NVIDIA's guide Inline PTX Assembly in CUDA

L02 The same guide: the constraint letter gives the kind of register, "r" a 32-bit unsigned register and "f" a 32-bit float register (also "h" for 16 bits, "l" for 64 bits and "d" for 64-bit floats). from: NVIDIA's guide Inline PTX Assembly in CUDA

In plain words

The tensor core instruction has no name in the kernel's own language, so the program inserts NVIDIA's instruction text directly and lists which of its variables stand for each numbered operand of that text. An equals sign in the list marks a variable that the instruction writes, and a letter says what kind of storage it needs. Converting the floats first, by rounding, keeps them a little closer to their true values than letting the hardware cut off the extra digits.

For a manager: a line that mixes two languages is a contract between them; ask which part each side owns, because a mistake in the binding compiles cleanly and computes the wrong thing.
