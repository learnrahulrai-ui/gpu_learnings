36. Lab 6: the places 8g + t, 8t + g and 8g + 2t, and who decides each factor

Each line uses only what the lines above it made. The grey note says which line it takes from. Fill every ____ on paper, then open CHECK. Under each piece of code, a panel reads it in English line by line. Any unfamiliar word: words used on this site.

The story

After computing its number n and the two smaller numbers g and t, each thread of the Lab 6 prelab reads 4 floats of a, 2 of b and 4 of c from GPU memory. The learner wrote the reads one at a time, and each one looked different: a multiplies g by 8, b multiplies t by 8, and c doubles t.

The learner's picture of an address was the usual one: the length of a line of the matrix times the line, plus the place in the line. Here the line came from the thread, not from the matrix, and the learner did not control the matrix at all, since it arrived as a plain address from the caller.

Where does each factor of these places come from, and what in them would change if the caller stored the matrices differently?

In plain words

Each thread must fetch the particular numbers that the hardware expects it to hold. Which numbers those are is fixed by the hardware; where they sit in memory is fixed by how the program stored its matrices. The address of each read is the two rules put together, and confusing them, or falling back on the habit of one thread per memory place, fetches the wrong numbers without any error.

For a manager: an address in this kind of code answers two separate questions, what the hardware wants and how the data is stored; ask which part of each formula answers which, so that a change to one does not break the other.
