01. Two papers: the grid square and the plane spot

Pencil. Paper. Every blank ____ is yours. Open CHECK only after you wrote a number.

Start from zero

The lab (MIT 6.S894 Lab 1, file mandelbrot_cpu.cpp) fills an output array out of 256 x 256 = 65536 whole numbers, run with img_size = 256 and max_iters = 1000. Each whole number is a count. To get the count for one grid square, the code first converts the square's two whole numbers (i, j) into two fractional numbers (cx, cy), and only (cx, cy) enter the counting loop. These are the two lines that do it, copied from the lab file:

float cx = (float(j) / float(img_size)) * 2.5f - 2.0f;
float cy = (float(i) / float(img_size)) * 2.5f - 1.25f;

Where you got stuck

"Row 2 column 2 will always mean row 2 column 2, right? ... From where you are inventing 4 columns?" / "Basically, I have two different papers, right?" / "What is the guarantee that ... with this middleman number, that number of iterations can change, right?"

Step 1: draw the two papers

Paper A holds whole numbers only: row i from 0 to 255 going down, column j from 0 to 255 going right. Paper B holds fractions: x from -2.0 to +0.5, y from -1.25 to +1.25. The two lines above are the only bridge between them. Nothing in the counting loop ever sees i or j.

  PAPER A (out array)                     PAPER B (plane)
  j = 0   1   2  ...  255                 x = -2.0 ............ +0.5
     +---+---+---+   +---+                   +---------------------+ y=-1.25
 i=0 |   |   |   |...|   |                   |                     |
     +---+---+---+   +---+                   |          *          |
 i=1 |   |   |   |...|   |   cx,cy lines     |     (cx,cy) spot    |
     +---+---+---+   +---+  ============>    |                     |
 ... |   |   |   |...|   |                   |                     |
     +---+---+---+   +---+                   +---------------------+ y=+1.25
i=255|   |   |   |...|   |
     +---+---+---+   +---+                   counting loop reads cx,cy
  out[i*256+j] = count  <================== and returns one count
DO: Grid square i = 64, j = 64. Calculate long-hand. 64 / 256 = ____ . Times 2.5 = ____ . Minus 2.0 gives cx = ____ . Same for i: times 2.5 = ____ . Minus 1.25 gives cy = ____ .
CHECK 
64 / 256 = 0.25
0.25 * 2.5 = 0.625
cx = 0.625 - 2.0  = -1.375
cy = 0.625 - 1.25 = -0.625

square (i=64, j=64)  -->  spot (-1.375, -0.625)

Step 2: the far edge

j never reaches 256, so j / 256 never reaches 1.0, so cx never reaches +0.5. Calculate the last column to see by how much it falls short.

DO: i = 128, j = 255. 255 / 256 = ____ . Times 2.5 = ____ . Minus 2.0: cx = ____ . For i = 128: 128 / 256 = ____ , times 2.5 = ____ , minus 1.25: cy = ____ . Gap between cx and +0.5 = ____ .
CHECK 
255 / 256       = 0.99609375
0.99609375*2.5  = 2.490234375
cx              = 0.490234375
128 / 256       = 0.5
0.5 * 2.5       = 1.25
cy              = 1.25 - 1.25 = 0.0
gap = 0.5 - 0.490234375 = 0.009765625  (= 2.5 / 256, one column step)

Step 4: where 2.5 and -2.0 come from

The lab author chose the window of paper B: x from -2.0 to +0.5, y from -1.25 to +1.25. Mandelbrot mathematics did not choose these numbers. The window width is the number multiplied, the window start is the number added.

DO: Width in x = 0.5 - (-2.0) = ____ . Width in y = 1.25 - (-1.25) = ____ . Now change the window to x from -1.0 to +1.0 and write the new cx line: cx = (j / 256) * ____ - ____ . Calculate cx for j = 64 with the new line: ____ .
CHECK 
x width = 2.5      y width = 2.5   (square window, square grid, no stretching)
new line: cx = (j / 256) * 2.0 - 1.0
j = 64  : 0.25 * 2.0 - 1.0 = -0.5

The grid square (64, 64) did not change. Its spot did. Its count changes with it.
