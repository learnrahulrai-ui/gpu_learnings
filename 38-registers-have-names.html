38. Lecture 5: registers have names, not places, one set per thread

The story

Lecture 5 of MIT 6.S894 builds the GPU's fastest storage from the inside. The registers are not separate cells in hardware but one large memory cut into banks, and the lecturer added a rule that sounded strange: a program can name a register, but it can never compute which register it wants.

The learner had been told that a warp holds 32 copies of the register set. That sentence contradicted everything else: if every thread has its own registers with its own values, what would a copy be? And if a thread may hold hundreds of variables, why could it not pick one of them by a computed number, the way it picks an element of an array in memory?

What is a register, whose is it, and why can no program choose one by a number computed while it executes?

In plain words

The fastest storage on the GPU has no addresses, only names written into each instruction, and every thread has its own set of them. That is why it is fast, and also why a program cannot pick one by a number it computes along the way: such data falls back to ordinary memory, which is far slower. Moving a value from one thread's storage to another's takes its own instruction.

For a manager: the fastest storage comes with rules about how it can be reached; ask whether a design needs computed access before blaming the hardware for slowness.

CHECK 
(3 + 1) * 4 bytes = 16 bytes per instruction; 13.4 * 10^12 * 16 = 214 * 10^12 bytes per

instruction, one bank per thread and no crossbar to cross, keeps up with every unit at once.
