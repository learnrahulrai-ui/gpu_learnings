T1. Adding two arrays: what actually limits the GPU

The story

Almost every GPU tutorial begins with the same program: take two lists of numbers, add them place by place, store the answers in a third list. It is the "hello world" of GPU programming, and it teaches the launch syntax well. What it usually does not teach is the one thing that decides how fast it goes.

The common belief is the one the learner of this site wrote down: put everything in parallel, because the GPU has many arithmetic circuits, and it will be fast. The GTX 1650 in this laptop has 896 of them. Adding 16.7 million pairs of numbers sounds like exactly the work they were built for.

Before believing that, ask what each addition needs besides the addition itself. Where do the two numbers come from, where does the answer go, and how long does carrying them take compared with adding them?

Work it out

L01 The standard program, as written in most tutorials: from: code

__global__ void add(const float *a, const float *b, float *c, int n) {
    int k = blockIdx.x * blockDim.x + threadIdx.x;
    if (k < n) c[k] = a[k] + b[k];
}
add<<<(n + 255) / 256, 256>>>(a, b, c, n);

Read the code in English, line by line

  1. __global__ void add(const float *a, const float *b, float *c, int n) {Define a function that executes on the GPU. It receives the addresses of three arrays of fractions in the graphics card's memory, a, b and c, and their length n. const means a and b are only read.
  2. int k = blockIdx.x * blockDim.x + threadIdx.x;Each thread computes its own number k: its block's number times the threads per block, plus its own number inside the block.
  3. if (k < n) c[k] = a[k] + b[k];If k is inside the arrays, read a at place k and b at place k, add them, and store the sum in c at place k.
  4. }End of the function.
  5. add<<<(n + 255) / 256, 256>>>(a, b, c, n);From the CPU, start the function with blocks of 256 threads, and enough blocks to cover all n places: n plus 255, divided by 256, rounded down.

L02 DO Take n = 16,777,216. Blocks = (16,777,216 + 255) / 256 rounded down = ____ . The thread with k = 1,000,000 is in block ____ with threadIdx.x = ____ . from: L01

CHECK 
blocks = 65536
1,000,000 / 256 = 3906.25 -> block 3906; 3906 * 256 = 999,936; 1,000,000 - 999,936 = 64
k = 1,000,000 is block 3906, threadIdx.x 64

L03 From L01, each k reads a[k] (4 bytes), reads b[k] (4 bytes), writes c[k] (4 bytes), and does one add. from: L01

L04 DO Bytes moved for n = 16,777,216: 12 x n = ____ . Adds = ____ . Adds per byte moved = ____ . from: L02, L03

CHECK 
bytes = 12 * 16,777,216 = 201,326,592
adds  = 16,777,216
adds per byte = 1 / 12 = 0.083

L05 Hardware fact: the GTX 1650 laptop GPU has a 128-bit memory bus, 16 bytes per transfer. With GDDR5 at 8 billion transfers per second per pin it moves 16 x 8 = 128 billion bytes per second; with GDDR6 at 12 billion, 192 billion. Your hardware table said "GDDR6 / GDDR5", so read your memory type with nvidia-smi -q. from: NVIDIA GTX 1650 laptop specifications

L06 DO Time to move L04's bytes at 128 billion bytes per second = ____ ms. At 192 billion = ____ ms. from: L04, L05

CHECK 
201,326,592 / 128e9 = 1.573 ms
201,326,592 / 192e9 = 1.049 ms

L07 Hardware fact: 896 FP32 units, each able to begin one add per cycle. Laptop clocks vary; this page assumes 1.5 billion cycles per second. Read yours with nvidia-smi -q -d CLOCK and redo the line. from: NVIDIA Turing layout, assumption

L08 DO Adds per second = 896 x 1.5 billion = ____ . Time for L04's adds = ____ ms. Ratio of L06's 128-billion time to this = ____ . from: L04, L06, L07

CHECK 
896 * 1.5e9 = 1.344e12 adds per second
16,777,216 / 1.344e12 = 0.0125 ms
1.573 / 0.0125 = 126

Connect the numbers

L10 DO Adds the GPU can do per byte the memory can move = (adds per second) / (bytes per second) = 1.344e12 / 128e9 = ____ . This program does ____ adds per byte (L04). from: L04, L05, L08

CHECK 
1.344e12 / 128e9 = 10.5 adds per byte to keep all 896 units busy

L11 DO Collect L04, L06, L08, L09, L10. Someone proposes making this program faster with 8-at-once instructions inside each thread, or with twice the threads. Write one sentence on what that changes in the time, and what would actually help. from: L04, L06, L08, L09, L10

CHECK 
Nothing measurable: the time is set by the 201 million bytes, and neither proposal moves fewer bytes.
What helps is fewer bytes (16-bit numbers instead of 32-bit halve them and so halve the time)
or more arithmetic per byte (doing several operations on each number while it is loaded).

Tempting answer that fails: "more parallel arithmetic, more speed". L08 puts the arithmetic at
0.0125 ms out of about 1.5.

In plain words

A GPU's arithmetic is so fast that, for simple jobs, the arithmetic is almost free and the real cost is carrying numbers in and out of memory. Adding two lists is such a job: the GPU spends over 99 percent of the time waiting for numbers to arrive.

For a manager: "the GPU has N cores" says little about speed. Ask how many bytes the job moves per calculation, and compare with what the card's memory can deliver.

The interviewer's next question

You must compute d = (a + b + c) times e for arrays of n numbers. Should it be three small kernels (add, add, multiply), or one kernel that does all of it? Give the bytes moved per place for each choice and the expected ratio of times.

CHECK 
three kernels: a+b -> t (12 bytes), t+c -> u (12), u*e -> d (12) = 36 bytes per place
one kernel   : read a, b, c, e and write d                  = 20 bytes per place
memory sets the time, so one kernel should take about 20/36 of the time: 1.8 times faster.
