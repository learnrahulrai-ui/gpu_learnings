The story

Lab 2 ends by combining everything: several independent sets of work inside each thread, many cores or SMs, and many threads per core or scheduler. Its last question asks whether the speedups of the separate techniques carry over when they are combined.

The obvious approach is to multiply: if one technique gave 2 times and another 5 times, expect 10 times together. A more careful-looking approach is to multiply the step-by-step speedups along the way from the baseline to the final version and check that the product equals the total. That second check feels rigorous. The learner warned about exactly this kind of step: knowing a definition is different from deriving whether the step means anything.

Does the step-by-step product test anything at all? And if not, which two measurements actually say whether a technique still helps once the others are in place?

Connect the numbers

L09 DO Collect L03 (the product always equals B / F), L04 (2 alone, 1.2 on top of T), L06 (2 times, then nothing), L08 (more sets, fewer threads fit). Write one sentence on why techniques that each help alone can stop helping together, and which pair of measurements tests it. from: L03, L04, L06, L08

CHECK 
Independent sets inside a thread and more threads per scheduler fill the SAME waiting cycles;
once one has filled them (L06: 2 chains already leave 0 cycles), the other has nothing left to
fill, and extra sets also cost registers that reduce how many threads fit (L08). The test is
B / I (the sets alone) against T / F (the sets on top of everything else), never the
step-by-step product, which matches B / F for any numbers (L03).

Tempting answer that fails: "the step-by-step speedups multiply to the total, so the techniques
combine independently". L03 shows that product can never come out different.

In plain words

Improvements that each work alone often work less together, because both are fixing the same problem: hardware waiting for results. Once the waiting is gone, the second fix has nothing to fix. A popular way of "checking" that improvements combine is actually guaranteed to agree, so it proves nothing.

For a manager: when two optimizations are each worth 2 times, do not budget for 4. Ask for a measurement of each one with the other already in place.

The interviewer's next question

With B = 120, I = 60, T = 12, F = 10 ms, someone says: "(B / T) x (T / F) = B / F, so the two techniques combine with no interference." What is wrong with the argument, and which ratios would you compare instead?

CHECK 
(B/T) * (T/F) = B/F for any numbers, so it carries no information about interference.
Compare B/I = 2 (independent sets alone) with T/F = 1.2 (independent sets after T): the gain
shrank from 2 to 1.2, so the techniques do interfere. Then look for the cause with register counts
(-Xptxas -v) and a sweep, not with the ratios alone.
