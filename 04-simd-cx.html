04. SIMD: eight cx values from one number

Each line uses only what the lines above it made. The grey note says which line it takes from. Fill every ____ on paper, then open CHECK. Under each piece of code, a panel reads it in English line by line. Any unfamiliar word: words used on this site.

The story

A processor core normally does one arithmetic operation on one number per instruction. The Ryzen in this laptop also has AVX2 instructions, which do the same operation on 8 numbers at once, held side by side in one 256-bit register. Lab 1 asks for the picture to be computed with these instructions. The idea is easy to say: handle 8 neighbouring places of the picture together. Saying it is not the hard part.

The first wall is the input. Each of the 8 places needs its own middleman pair, and the 8 values must be built before any arithmetic can begin. The vector code builds them with a line containing the numbers 7, 6, 5, 4, 3, 2, 1, 0, which appear nowhere in the problem. The learner called them alien, and asked why the problem never mentions them.

Can those numbers be forced out of the original cx line, so they stop being something to remember? And a harder question: the vector code matched the original code exactly on the 256 by 256 picture. Is that proof that the method is exact?

Guess first

At picture size 1000, the 8-at-once method and the plain method each compute 1000 values of cx. How many of the 1000 do you think differ, even slightly?

Work it out

L01 The scalar lab code makes the middleman pair for one (i, j), copied without change: from: code

float cx = (float(j) / float(img_size)) * 2.5f - 2.0f;

Read the code in English, line by line

  1. float cx = (float(j) / float(img_size)) * 2.5f - 2.0f;Turn j and img_size into fractions, divide j by img_size, multiply by 2.5, subtract 2.0, and keep the result in a fraction named cx. The f after a number marks it as a 32-bit fraction (a float).
  2. float cy = (float(i) / float(img_size)) * 2.5f - 1.25f;Do the same with i, but subtract 1.25, and keep the result in cy.

L02 Your machine gave img_size = 256. Your CPU is a Ryzen 5 4600H, which has AVX2. from: your output

L03 An AVX2 variable of type __m256 holds 256 bits. A float holds 32 bits. 256 / 32 = 8, so one __m256 holds 8 floats, at index 0 to index 7. from: L02

L04 An instruction named _mm256_..._ps does one operation on all 8 floats: index 0 with index 0, index 1 with index 1, up to index 7 with index 7. from: L03

L05 The vector code puts 8 neighbours into one __m256: same i, and j, j+1, ..., j+7 at index 0, 1, ..., 7. So its j for loop steps by 8. from: L03, L04

L06 Your vector code, copied without change: from: your code

__m256 offsets = _mm256_set_ps(7, 6, 5, 4, 3, 2, 1, 0);
float  dx      = 2.5f / float(img_size);
for (uint64_t i = 0; i < img_size; ++i) {
    float  cy     = (float(i) / float(img_size)) * 2.5f - 1.25f;
    __m256 cy_vec = _mm256_set1_ps(cy);
    for (uint64_t j = 0; j < img_size; j += 8) {
        float  cx     = (float(j) / float(img_size)) * 2.5f - 2.0f;
        __m256 cx_vec = _mm256_fmadd_ps(offsets, _mm256_set1_ps(dx), _mm256_set1_ps(cx));
        /* the while loop works on cx_vec, cy_vec here */
    }
}

Read the code in English, line by line

  1. __m256 offsets = _mm256_set_ps(7, 6, 5, 4, 3, 2, 1, 0);Make a 256-bit variable named offsets that holds 8 fractions. The instruction _mm256_set_ps fills them from index 7 down to index 0 with the listed values, so index k holds k.
  2. float dx = 2.5f / float(img_size);Make one fraction dx: 2.5 divided by img_size.
  3. for (uint64_t i = 0; i < img_size; ++i) {Give i the values 0 up to img_size minus 1, one after another.
  4. float cy = (float(i) / float(img_size)) * 2.5f - 1.25f;Compute one cy for this value of i, the same way as the scalar code.
  5. __m256 cy_vec = _mm256_set1_ps(cy);Copy that one cy into all 8 indexes of a 256-bit variable named cy_vec.
  6. for (uint64_t j = 0; j < img_size; j += 8) {Give j the values 0, 8, 16, and so on: each step of this loop covers 8 values of j at once.
  7. float cx = (float(j) / float(img_size)) * 2.5f - 2.0f;Compute one cx, for the j this loop is at, the same way as the scalar code.
  8. __m256 cx_vec = _mm256_fmadd_ps(offsets, _mm256_set1_ps(dx), _mm256_set1_ps(cx));At each of the 8 indexes, multiply offsets by dx and add cx, all in one instruction (fmadd = fused multiply-add). Keep the 8 results in cx_vec.
  9. /* the while loop works on cx_vec, cy_vec here */A note for people: the loop that uses cx_vec and cy_vec goes here; it is not copied in this block.
  10. }End of the block opened by the matching brace above.
  11. }End of the block opened by the matching brace above.

In plain words

Doing 8 things at once forces you to describe the 8 things with one rule. Here the rule is: neighbour k sits k steps of dx from the first one. Finding that rule is the actual work; typing the intrinsic is not.

For a manager: a test that succeeds on round numbers can hide a defect that only appears on ordinary numbers. Ask what the test size was and why.

The interviewer's next question

How would you make the 8-at-once method give exactly the plain method's values at any picture size, and what does it cost?

CHECK 
Build the 8 values of j + k as fractions in one register, then apply the same divide, multiply and
subtract as the plain line, at all 8 at once. The rounding then happens in the same steps as the
plain code. Cost: an 8-at-once divide per block of 8, the step the shortcut was avoiding.
Also read the plain code's machine listing: the compiler may fuse its multiply and subtract into
one multiply-add, and the 8-at-once version must then do the same to match.
