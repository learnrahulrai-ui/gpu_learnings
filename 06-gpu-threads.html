Step 1: one thread's columns

Every thread runs the whole function. threadIdx.x is 0 to 31, blockDim.x is 32, i runs 0 to 255 in every thread.

DO: Thread 7, row i = 0: write every j it visits: ____ . How many columns per thread per row: ____ . Which thread writes column 103: ____ .
CHECK 
thread 7: 7, 39, 71, 103, 135, 167, 199, 231     (8 columns = 256 / 32)
column 103 = 3*32 + 7 -> thread 7

Step 2: "nearby" is across threads, at the same moment

The hardware does not run 32 threads separately. It runs them as one warp: 32 threads execute the same instruction together, each with its own registers. So when the store out[i*256 + j] = iters executes for visit k, it executes for all 32 threads at once, and the 32 addresses go to memory as one request. Within one thread, 7 and 39 are far apart (128 bytes). Across threads, at visit k, the addresses are side by side. Both statements are true; they describe different axes of the drawing.

             visit k=0     visit k=1     ...   visit k=7
thread  0 -> col   0       col  32             col 224
thread  1 -> col   1       col  33             col 225
thread  2 -> col   2       col  34             col 226
  ...          ...           ...                 ...
thread 31 -> col  31       col  63             col 255
             \_______/
             ONE store instruction, 32 addresses
             one THREAD   = one row of this table, left to right: 0, 32, 64 ... (far)
             one REQUEST  = one column of this table, top to bottom: 0..31  (near)

Each out element is a uint32_t = 4 bytes. Memory moves data in 32-byte sectors.

DO: Row 0, visit k = 0. Byte offset of thread t's write = 4 x (0 x 256 + t). Thread 0: ____ , thread 31: ____ . Bytes spanned = ____ . Sectors touched = ____ .
CHECK 
thread 0  -> byte 0
thread 31 -> byte 124   (writes bytes 124..127)
span = 128 bytes = 4 sectors of 32 bytes

Step 5: why 22.75x and not 32x

A warp executes one instruction for all 32 threads, so the while loop of one visit runs until the slowest of the 32 threads is done; the finished threads wait masked off. This is page 04's frozen lanes again, with 32 lanes. Row 40, visit k = 5 (columns 160 to 191), real counts: slowest = 1000, sum of the 32 counts = 1334.

DO: Lane-passes executed by that visit = 32 x ____ = ____ . Useful = ____ . Useful percent = ____ . Whole image, from the real counts: useful 16274722, executed 23609216. Predicted speedup of 32 threads over 1 thread = 32 x useful / executed = ____ . Measured = 403.435 / 17.732 = ____ .
CHECK 
row 40 visit 5: 32 * 1000 = 32000 lane-passes, 1334 useful = 4.2 percent
whole image: 16274722 / 23609216 = 0.6893
predicted = 32 * 0.6893 = 22.06
measured  = 403.435 / 17.732 = 22.75
The counts alone predict the measured speedup within 0.7.
