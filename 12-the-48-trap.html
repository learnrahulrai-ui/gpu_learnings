The story

The second prelab program, warp_scheduler.cu, measures how fast the GPU gets as more threads are given to it. It sweeps a multiplier from 1 to 48 and prints a table. The file was written for the course's GPU, and a number from that GPU is written inside it.

The learner first had to separate two facts that are easy to merge: how many SMs the chip has (fixed by the hardware, 14 on this laptop) and how many 32-thread units each SM is given (decided by the program at launch). Asked whether knowing one tells you the other, the learner's answer was no, and that answer is the key to this page.

The file contains the number 48. Where did it come from, and what happens to every line of the printed table when the program executes on a GPU that has 14 SMs?

Your words: "Confirm me this part, okay? I have 14 SMs. Yes or no?" / "just because I have SMs doesn't mean I know how many threads or schedulers you run. That is a different piece of information, yes or no?" / "Okay, so now what exactly I have to do?"

L01 A launch <<<B, T>>> makes B blocks of T threads. Each block executes on one SM, a unit of the GPU chip. Your GTX 1650 has 14 SMs. from: CUDA definition, your hardware table

L02 An SM handles a block's threads in units of 32, called warps. Number of SMs and number of warps per SM are separate facts: the first is fixed by the chip, the second by the launch. from: CUDA programming guide, your words

L03 From the report on your file warp_scheduler.cu (the file itself was not in the chat): T = 64 threads per block; each thread takes 32 numbers; for each number it executes tmp += tmp * 3.0f 263 x 20 times, each step reading the previous step's tmp; the file sets N = 2048 x 48 x multiplier with multiplier from 1 to 48, and launches N / 2048 blocks. from: report on your file

In plain words

Lab files written for one machine carry that machine's numbers inside them. Executed on another machine they still produce a table that looks fine, and every line of it can be wrong in a way the table itself does not show. Before trusting a sweep, find every hardware number written into the program and replace it with yours.

For a manager: a benchmark copied from a vendor or a course measures their hardware's shape, not yours, until someone checks the constants.
