02. The while loop by hand

Each line uses only what the lines above it made. The grey note says which line it takes from. Fill every ____ on paper, then open CHECK. Under each piece of code, a panel reads it in English line by line. Any unfamiliar word: words used on this site.

The story

Every place (i, j) of the picture has already been turned into a middleman pair (cx, cy). Now the arithmetic itself. The lab code keeps a second, moving pair of numbers, begins it at (0, 0), and repeats the same handful of lines on it: square it in a particular way, add the middleman pair, check how far it has moved from (0, 0). When it gets farther than 2, the loop is left, and the number of repetitions done is stored in out.

The learner objected twice, and both objections are worth having. First: if the moving pair begins at (0, 0), squaring zero gives zero, so how can anything ever change? Second: the chat kept using a word for what the point does, a word the learner had never been given a meaning for, and the learner asked what it meant, since a point does not move. Both questions can be settled only by executing the code's lines by hand with real numbers, so that is the work here.

Keep one question in mind while you calculate: could you have predicted any of these counts before doing the work?

L01 The lab file mandelbrot_cpu.cpp, for one (i, j), has these lines, copied without change: from: code

float cx = (float(j) / float(img_size)) * 2.5f - 2.0f;
float cy = (float(i) / float(img_size)) * 2.5f - 1.25f;
float x2 = 0.0f;
float y2 = 0.0f;
float w = 0.0f;
uint32_t iters = 0;
while (x2 + y2 <= 4.0f && iters < max_iters) {
    float x = x2 - y2 + cx;        // line A
    float y = w - x2 - y2 + cy;    // line B
    x2 = x * x;                    // line C
    y2 = y * y;                    // line D
    float z = x + y;               // line E
    w = z * z;                     // line F
    ++iters;
}
out[i * img_size + j] = iters;

Read the code in English, line by line

  1. float cx = (float(j) / float(img_size)) * 2.5f - 2.0f;Turn j and img_size into fractions, divide j by img_size, multiply by 2.5, subtract 2.0, and keep the result in a fraction named cx. The f after a number marks it as a 32-bit fraction (a float).
  2. float cy = (float(i) / float(img_size)) * 2.5f - 1.25f;Do the same with i, but subtract 1.25, and keep the result in cy.
  3. float x2 = 0.0f;Make a fraction named x2 holding 0.
  4. float y2 = 0.0f;Make a fraction named y2 holding 0.
  5. float w = 0.0f;Make a fraction named w holding 0.
  6. uint32_t iters = 0;Make a 32-bit whole number named iters holding 0. It will count repetitions.
  7. while (x2 + y2 <= 4.0f && iters < max_iters) {Before each repetition, test two things: is x2 plus y2 at most 4, and is iters below max_iters? If both are true, do the lines inside the braces once and test again. If either is false, continue after the closing brace.
  8. float x = x2 - y2 + cx; // line ALine A: subtract y2 from x2, add cx, keep it in x.
  9. float y = w - x2 - y2 + cy; // line BLine B: from w subtract x2, then subtract y2, then add cy, keep it in y.
  10. x2 = x * x; // line CLine C: multiply x by itself and put the result in x2, replacing the old x2.
  11. y2 = y * y; // line DLine D: multiply y by itself and put the result in y2.
  12. float z = x + y; // line ELine E: add x and y, keep it in z.
  13. w = z * z; // line FLine F: multiply z by itself and put the result in w.
  14. ++iters;Add 1 to iters.
  15. }End of the block opened by the matching brace above.
  16. out[i * img_size + j] = iters;Store the whole number iters into the array out, at place number i times img_size plus j.

In plain words

The Mandelbrot picture is used in this course for one reason: its work is uneven and unpredictable. Most real workloads look like this. Some customer requests are cheap and some are expensive; some pages of a document are blank and some are dense. Splitting work into equal-sized piles of items does not split the effort equally.

Every speed trick in the pages that follow has to deal with the fact found here: places that need 1000 repetitions sit next to places that need 1, and nobody knows which is which in advance.
