L01 The lab file mandelbrot_cpu.cpp, for one (i, j), has these lines, copied without change: from: code

float cx = (float(j) / float(img_size)) * 2.5f - 2.0f;
float cy = (float(i) / float(img_size)) * 2.5f - 1.25f;
float x2 = 0.0f;
float y2 = 0.0f;
float w = 0.0f;
uint32_t iters = 0;
while (x2 + y2 <= 4.0f && iters < max_iters) {
    float x = x2 - y2 + cx;        // line A
    float y = w - x2 - y2 + cy;    // line B
    x2 = x * x;                    // line C
    y2 = y * y;                    // line D
    float z = x + y;               // line E
    w = z * z;                     // line F
    ++iters;
}
out[i * img_size + j] = iters;

L02 Your machine gave img_size = 256 and max_iters = 1000. from: your output

L03 The pair (cx, cy) is the middleman pair. Nothing inside the while loop writes cx or cy, so it stays fixed for this (i, j). from: L01

L04 The values x2, y2, w begin at 0.0 and iters begins at 0. Lines C, D, F write new x2, y2, w every time. from: L01

L05 A repetition = lines A to F, then ++iters, executed once in that order. from: L01

L06 Before every repetition the while loop checks x2 + y2 <= 4.0f and iters < 1000. Both true: do one repetition. Either false: leave the loop. from: L01, L02, L05

L07 After leaving, out[i*256 + j] receives iters, which equals the number of repetitions done. from: L01, L05, L06

L08 DO Repetition 1 begins with x2 = y2 = w = 0 (L04). Line A gives x = 0 - 0 + cx = ____ . Line B gives y = ____ . from: L01, L04

CHECK 
x = 0 - 0 + cx     = cx
y = 0 - 0 - 0 + cy = cy
The 0.0 in L01 is why repetition 1 lands exactly on the middleman pair.
Beginning at 0 does change things: it adds cx and cy.
